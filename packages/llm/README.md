# @littlesheep/llm

适配 OpenAI-compatible 聊天与流式接口，提供响应校验、有限重试、usage 归一化和请求类型。公开入口为 `src/index.ts`；本包不决定 Workflow、工具权限、Context 来源或长期状态，也不持久化会话。

## 请求与失败边界

- 请求取消、自有 deadline 与 Provider 错误分开表达。只重试被判定为可重放的传输错误和限流；认证、无效请求及调用方取消不重试。
- 重试次数与等待有上限；遵循 Provider 的 `Retry-After`，但仍受配置最大延迟约束。每次尝试向上层报告，避免隐藏传输重试被统计为单次请求。
- 流式响应必须收到 `[DONE]` 或明确的 `finish_reason` 才算完成。有内容但未收到完成信号时按可重试传输失败处理，不能把截断文本当成结算回复。
- `ChatRequest.onProviderResponse` 是本地、可等待的物理响应回执端口，不发送给 Provider。收到实报用量后先等待上层持久化，再校验正文或发起重试；流式中断也交出已经收到的用量。回执持久化失败不可重放已收费请求。
- 输入、输出必须是有效实报整数，缺失不能补成 0；总量缺失时仅从这两个实报字段求和。无效缓存／推理子集保持未知，不抹掉有效的主用量。EOF 的最后一帧和独立 usage 帧都参与解析。
- Provider 文本中编码的 DSML 工具调用只有在完整、有效且属于已注册工具时才转成结构化调用。畸形、截断或未授权标记失败关闭；普通引用或代码示例保持原文。
- Provider 密钥不得进入日志、快照或错误正文。协议差异留在本包适配，不向上层扩散特例。
- 网关差异也留在本包：`ChatRequest.conversationId` 是调用方给出的会话身份，需要稳定会话头的端点（opencode Go 的 `x-opencode-session`，缺头时直接 `400 MissingSessionID`）由本包按端点补上；没有对话上下文的调用用客户端自身的稳定 id，保证请求仍可路由。请求同时以 `User-Agent: LittleSheep/0.1` 标识来源，而不是退化成通用 HTTP 库的名字。这些头只上传输层，不进入请求体、快照或错误正文。
- 上层传入的 `providers[].headers` 随每次请求发出，供网关自己的路由头使用；Provider 显式配置的同名头优先。

包内仅依赖 `zod`；上层 Context、Harness 与 Runner 决定何时发起请求。客户端、重试、请求时限、流式、DSML 与网关请求头契约由本包定向测试覆盖。
