**窗口拖拽带与全局导航的分工（chali，2026-09-28）**：侧栏列现在整列贯通窗口顶边（`styles/03-shell-sidebar.css` 的 `.sidebar { grid-row: 1 / -1 }`），顶部条从它的右边缘才开始，所以"整宽标题栏"这条拖拽捷径不再存在。`global-titlebar.tsx` 因此导出 `WindowDragRegion`——一个不画像素、不可聚焦的 `div`，带 `-webkit-app-region: drag` 与 `startWindowDrag`/`moveWindowDrag`/`endWindowDrag` 指针桥（与标题栏同一份函数），由 `app-view.tsx` 以 `.window-drag-band` 渲染在 `.app` 的 `grid-column: 1; grid-row: 1`，`z-index: 21` 盖过侧栏本体与其分隔条；设置浮层里由 `settings/workspace.tsx` 渲染同一组件的第二份，覆盖设置侧栏那条 32px 带。真实窗口实测（1280×820）：band 为 `x=0 w=292 h=32`、`-webkit-app-region: drag`，折叠时随网格列归零；在同一窗口里分别对 band 与标题栏做一次真实指针拖动，窗口位移都是请求的 24×12（纯 CSS `app-region` 的对照元素在同一探针里位移为 0，说明这类合成输入下真正驱动窗口的是指针桥，而 app-region 是真实鼠标下的同款保底，与标题栏一直是同一套两件套）。**全局导航控件（侧栏开关、前进/后退）继续留在顶部条**：侧栏折叠时它们必须仍然可达（放进侧栏会随折叠一起消失），而顶部条也是设置浮层唯一没有覆盖的一条带；`aria-label`、`aria-expanded`、禁用态与悬停提示均未改动，真实指针点击开关会依次折叠与展开（`chat-layout-stability.test.ts` 的 chali 用例钉住结构与 `inert` 边界）。

**拖拽带曾经吃掉整个窗口（chali 首轮实测，2026-09-28）**：`.window-drag-band` 最早写成 `position: absolute; inset: 0`，而当时的 `.app` 并不是定位包含块，于是这条"32px 的网格带"逃到**视口**上，实测 `1280×820` 的全窗透明层：`elementFromPoint` 在侧栏导航、侧栏分隔条和顶部条三个控件的中心全部返回 `window-drag-band`，侧栏点不动、拖宽量 `276 → 277`（应到 366）、开关也点不到——`.app` 缺 `position: relative` 时，绝对定位子元素的 `grid-column` / `grid-row` 不生效。修法是让这条带**当普通网格项**（只留 `grid-column: 1; grid-row: 1`，没有 `position`/`inset`）：它和侧栏占同一个网格区域并叠在上面，宽度因此直接跟着网格列走，不需要第二个宽度计算。修后同一探针：band 为 `x=0 w=292 h=32`、侧栏导航与三个顶部条控件全部 `reachable`、侧栏拖宽 `276 → 366`、band 内真实指针拖动使原生窗口位移 `(206,99) → (536,264)`。**注意**：`.app` 上不能加回 `position: relative` 之外的定位技巧，band 也不能改回绝对定位。

**侧边栏的蓝紫洗色减半**（2026-09-26）：渐变方向保留，透明度从 `rgba(86,148,255,0.16)` / `rgba(150,104,255,0.19)` 降到 **`0.08` / `0.10`**（色调不变）。按 token 合成计算：卡片底色（`--bg #141414` 上叠 36% 的 `--surface #202020`）为 rgb(24,24,24)，洗色对它的偏移顶端由 `+37`（蓝）降到 **`+19`**、底端由 `+44`（蓝）/`+24`（红）降到 **`+23`/`+13`**——两端都正好减半。`sidebar-tint-depth.test.ts` 把"浅"这一侧钉住（顶端 ≤ 0.10、底端 ≤ 0.12，且底端仍强于顶端，保证方向感），免得以后又被调重。
**磨砂层盖到洗色之上**（2026-09-27）：洗色此前是 `.sidebar-surface::before` 上**唯一**的一层 `background-image`，而背景图永远画在背景色之上，于是它压在 `--sidebar-glass-fill` 上面，卡片读起来像一块蓝紫色面板，而不是一块带洗色的灰玻璃。现在把同一份填充再作为最上面的一层图像写一次（排在洗色**前面**，先写的画在上面），玻璃就回到洗色之上，洗色只从它下面透出一点光——"淡淡的一层，像磨砂玻璃"说的正是这个层级关系。两个 alpha 一个都没动，仍是 `0.08` / `0.10`，所以 `sidebar-tint-depth.test.ts` 钉住的浅度继续成立；这次改的是**顺序**，没有动其中一个令牌去换另一个。按 token 合成计算（`--bg #141414` → 36% `--surface #202020` → 洗色 → 再一层 36% 灰）：顶部由 `rgb(29, 34, 43)` 变为 `rgb(30, 33, 39)`、底部由 `rgb(37, 32, 47)` 变为 `rgb(35, 32, 42)`，洗色带来的蓝-红偏移两端都降到原来的 **64%**（−36%），而整体明度只动 1–2/255 量级——是"变淡"，不是"变暗"或"变亮"。唯一的副作用是卡片本底（不含洗色的那层灰）由 `rgb(24, 24, 24)` 抬到 `rgb(27, 27, 27)`，因为两层 36% 的填充叠在一起；3/255 在深色玻璃上不可辨。要再淡仍只调那两个 alpha，不要取消上面这层玻璃。
**任务胶囊移到聊天区最上方，可重命名、可终止、历史自动折叠**（2026-09-27，此前 2026-09-26 在标题栏）：`running-pill.tsx` 的胶囊现在浮在**聊天列顶部、侧边栏右侧**（`.running-pill-shell` 绝对定位在 `.chat` 顶边，与底部 `.composer-shell` 对称；`pointer-events: none` 的壳里只有胶囊本身可点），不再占标题栏。胶囊**宽度自适应**：只包内容——圆环（有指令在跑时旋转）+ 对话标题，运行记录存在时才有右侧摘要段（运行中为指令 + 耗时、空闲为"上次运行 …"），从未运行的对话不占那段位置。**双击标题就地重命名**（Enter / 失焦提交、Esc 取消，`normalizeRenameDraft` 只提交真正不同的非空名，走 `session-actions.ts` 的 `renameSession`）。点开的浮层分「进行中 / 已结束」两段：**进行中的每条指令带终止按钮**（`onStop` = `chat/run-actions.ts` 的 run 级 `stop`，行内圆形方块图标就地绘制，因为 `ui/icons.tsx` 冻结）；**已结束超过 6 条时按 dsh（deepseek harness）的方式自动折叠**——保留最新 4 条，其余收进"展开更早的 N 条 / 收起"开合行（`foldFinishedCommands` 纯函数，`FINISHED_FOLD_THRESHOLD` / `FINISHED_FOLD_VISIBLE` 可调）。胶囊与浮层都换成**输入框同款磨砂玻璃**（`var(--composer-surface)` + `blur(18px) saturate(135%)`、无描边，浮层圆角对齐 `var(--radius-composer-input)`）；两者都不嵌在任何带 `backdrop-filter` 的祖先里（浮层 portal 到 `document.body`），模糊有真实背景可采。聊天内容被约束在两条边之间：`.chat:has(> .running-pill-shell) .messages` 用 `margin-top: var(--task-pill-inset-top)` 把视口上缘裁在**胶囊上缘**（内容可从胶囊玻璃下滚过，但永不出现在它上方），`padding-top`/`scroll-padding-top` 取 `--task-pill-overlay-height`；`.messages` 的 `margin-bottom: var(--composer-shell-inset-bottom)` 把下缘裁在**输入框下缘**。数据仍只来自 `chat` 已有的活动记录：`titlebar-task.ts` 把会话列表、转录与聊天时钟折成 `titlebarTask`，经 `chat` 投影（连同 `renameSession` / `stop`）交给 `chat-view.tsx` 渲染。布局与材质由 `chat-layout-stability.test.ts` 的「floats the task pill…」用例钉住，折叠/重命名/终止按钮由 `running-pill.test.ts` 钉住。
**分叉对话**（2026-09-27）：`session-actions.ts` 的 `branchConversationFromMessage(messageId)` 调 `branchSession`（`POST /sessions/:id/branch`），Main 用同一套 `SessionManager` 按任意已保存的用户消息或已完成助手回复截取历史，重绑消息所属会话并继承项目/工作区/权限模式，标题取「原名（分支）」；前端刷新列表并切进分支。入口在用户和助手消息行上（见 `chat/README.md`）。
**被置顶/取消置顶的那一行自己也要移动**（2026-09-26，实机定位）：置顶把一行从"日期组"挪到"置顶组"，两个组各自持有自己的 `useSidebarListDrag` FLIP pass，因此这一行在两边都是"新 id"，**邻居会让位、它自己却瞬移**——真实窗口实测（点击第 3 行的置顶按钮后 60ms）：被置顶行已经在终点 `369`，而另外两行还在 `396/431` 途中。修复在 `session-row.tsx`：行自己记住上一次绘制的 `getBoundingClientRect()`（`useLayoutEffect` 每次渲染更新），当 `pinned` 在这一帧发生变化时，用同一档时长与缓动（`SIDEBAR_LIST_PUSH_DURATION_MS` = 320ms、`cubic-bezier(0.2, 0.8, 0.2, 1)`）从"旧位置 → 新位置"补一段 WAAPI 位移动画。只有"跨组"这一帧才会补，普通重排仍由列表的 FLIP 负责，不会双重动画。修复后实测：三行同时在飞（`乙|320|true`、`丁|320|false`、`丙|320|false`），被置顶行在 60ms 时位于 `396`（旧 445 → 新 369 之间）。
**列表位移与选中淡入放慢到原来的一半**（2026-09-26）：侧边栏列表用 `useListReorderAnimation` 做 FLIP，`SIDEBAR_LIST_PUSH_DURATION_MS` 由 160ms 改为 **320ms**——点击会话导致的重排、置顶/取消置顶在"置顶组"与"日期组"之间移动时的行位移、以及拖动时的让位，都走同一次 FLIP，因此一起变慢。会话行自己的选中填充另有一条 CSS 过渡：`.session-item.active` 的 `transition-duration: calc(var(--motion-fast) * 2)`（140ms → **280ms**），只影响"选中"这一侧的淡入，悬停反馈仍是 140ms。真实窗口实测：置顶/取消置顶触发的行动画 `duration: 320`、缓动 `cubic-bezier(0.2, 0.8, 0.2, 1)`；点击后的活动行 `transition-duration: 0.28s`，非活动行仍是 `0.14s`。
**会话行有三个快捷控件**（2026-09-26）：置顶、归档、以及"…"多功能菜单，按这个顺序排在行尾；归档从菜单里提出来做成一键按钮，是因为它是和置顶同一类的日常整理动作，走菜单要多两次点击却不产生任何决定（菜单里的"归档对话"仍然保留）。三个控件都用共享的 `.sidebar-section-action` 角色，`.session-row-actions` 的预留宽度相应改成三个控件的宽度（`(size * 3) + (gap * 2)` = 84px，标题栏因此少 29px）。真实窗口实测：控件顺序为 `session-pin-action` → `session-archive-action`（`aria-label="归档对话"`）→ `.sidebar-action-menu`，标题右边界 162px、控件区左边界 166px（不重叠），点击归档后该会话从列表消失。
侧边栏的玻璃材质里带一层**从上到下的淡蓝→淡紫晕色**（`--sidebar-tint-top` / `--sidebar-tint-bottom`，2026-09-26；2026-09-27 起磨砂填充盖在它上面，见本文件「磨砂层盖到洗色之上」）：它只加在 `.sidebar-surface::before` 上，与压在它之上的那层玻璃填充共同构成该伪元素的两层 `background-image`（洗色写在**后面**、玻璃写在**前面**，先写的画在上面），所以右侧工作区面板保持无染色玻璃，两者继续共用同一条材质规则；不要把它并进 `--sidebar-glass-fill`，也不要给 `.sidebar-surface` 本体加 `background-image`（`chat-layout-stability.test.ts` 锁住"表面本体透明、材质在 `::before`"）。两个 alpha 都压在 0.2 以下：2026-09-26 测得的真机读数（1280×860、DPR 1.5，取侧边栏上/中/下三带像素均值）为顶部 `rgb(50, 58, 74)`、中部 `rgb(41, 42, 65)`、底部 `rgb(47, 39, 67)`，通道关系由"蓝>绿>红"过渡到"蓝>红>绿"；那一次上面还没有磨砂层，所以比现在更艳。文字仍是 `--text` 落在深色底上，对比度远高于 AA。要更强或更弱只调这两个令牌。
