# @littlesheep/tools

提供内置工具、工具注册表与所有宿主工具共用的 Tool Execution Service。公开入口为 `src/index.ts`；Harness／Runner 决定调用时机，本包拥有工具验证与执行边界。

## 执行契约

- 内置、插件和 run-scoped 工具必须经过同一服务：来源解析、schema 校验、权限与必要批准、超时／取消、资源冲突调度、输出清洗和有界调用记录。
- 工具只能执行受约束动作；路径和权限在 Main 执行时复核。工具不得自行绕过工作区边界、审批或执行日志，也不得重复索取同一授权。
- `ToolContext.containerRoot` 表示活动应用数据根的逻辑容器分类，不是 OS 沙箱。核心源码硬只读优先于完全访问和单次批准；不可静态证明范围的命令按 `unknown` 处理。
- 现有文件写入需有完整、未清洗的读取观察；提交时按内容哈希检查版本。观察只证明模型读取过什么，不代替副作用前像或回滚检查点。
- 工具失败用有界 `errorKind` 与明确状态表达。长输出截断并保留原始长度、退出码、超时／取消等事实，不把 partial 结果当完整输出。
- 工具目录在会话内保持固定；单轮准入范围只限制执行，不通过改变模型所见 schema 来表达授权。

包内模块分别拥有注册、执行调度、授权、清洗、路径保护和内置工具。用户文件不由本包拥有；访问只发生在获授权路径和调用生命周期内。

## 依赖与验证

依赖公共契约、安全、会话、记忆和文档能力；不依赖配置包。各模块测试覆盖注册、授权、调度、文件观察和内置工具。涉及文件观察／修改使用 `verify:file-consistency-faults` 与 `verify:desktop-file-consistency`；真实桌面审批和恢复由对应 Electron 验收覆盖，入口见 [脚本索引](../../scripts/README.md)。
