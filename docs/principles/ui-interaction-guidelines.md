# UI 交互规范

LittleSheep 界面应安静、连贯且易于理解。当前产品保留半透明磨砂玻璃与圆润风格；共享颜色、间距、圆角、层级和控件令牌优先于局部字面值。

## 信息与反馈

默认先呈现用户要做的事、当前状态和结果。复杂过程、来源与证据按需展开；失败、风险、权限拒绝和待用户决定不能折叠到难以发现的位置。

空、加载、无数据、不可用和失败是不同事实，应使用一致的共享状态表达。重试、继续、保存和取消只在 Runtime 或服务支持该动作时出现；操作失败要保留原因与可恢复内容。

不可逆操作说明对象、影响和保留内容，并要求明确确认。按钮文案只表达真实可执行动作。进度、权限、路径和运行状态来自应用事实，不由模型文本替代。

## 视觉与动效

材质用于区分层级，不为每个容器叠加玻璃、边框或阴影。保持稳定的表面色、清晰的前景对比和一致圆角；语义危险、成功、警告和中性状态通过共享令牌表达。

动效只帮助解释出现、消失或状态变化。动效应短、可打断，并遵守系统减少动态效果设置；不能让关闭、切换或关键操作等待纯装饰动画。

## 操作与可达性

键盘用户应能进入、浏览、执行和退出常见交互；焦点在弹层打开、关闭、失败和重试后有明确归属。不可操作的状态要有真实 disabled 语义和可见理由，不只依赖颜色。

交互表面应适配最小支持窗口和缩放。窗口 chrome、拖动区和顶栏控件需按平台原生命中结果验证；DOM 命中或合成点击不能替代系统级命中证据。

界面实现细节由对应 package 与测试维护。只有新的长期交互原则或正式验证入口变化时才更新本文；一次性实测过程留在测试输出或 Git 历史。
