## 总目标

把 LS 的核心能力收束到三件事：

- 不失忆：对话、项目、长期记忆、每日流水、经验库和执行记录通过记忆树统一注册、检索和按需注入上下文。
- 高效执行任务：解放用户生产力，让用户专注于想法和目标，LS 负责把想法拆解、执行、验证并落地；精准判断真实需求，避免大炮打蚊子，复杂任务用结构化任务书推进，简单任务保持轻量。
- 持续能力进步：从已完成任务中提炼可复用经验，但用阈值和审批避免记忆污染。

本任务书只规划核心 agent 能力，不展开新的视觉重设计。所有 UI 落地仍遵守 `docs/principles/ui-interaction-guidelines.md`。

## 总设计理念

用户正常使用时无感，但始终保留高度自定义和管理 agent 的权利。

- 默认自动：需求校准、局部重规划、记忆索引、自动整理和低风险恢复在后台完成，不要求用户理解内部状态机。
- 安静介入：只有缺少关键决策、权限风险、自动恢复耗尽或不可逆操作时才打断用户。
- 渐进披露：默认先显示结论、当前状态和关键产物；任务书、执行证据、记忆来源、命令原始输出、阈值和高级策略按需展开，失败、风险和待用户决策项始终可见。
- 高度可管：用户通过设置管理模型、权限和高层策略，通过记忆文件视图编辑 `SOUL.md`；底层分支、Atom 和自动写入由 Runtime 按可审计策略治理。
- 可追溯可撤销：自动行为保留理由、来源和变更记录；能够恢复的操作必须提供恢复或撤销路径。
- 默认值可用：不开任何高级设置时 LS 也应稳定工作；自定义能力不能成为正常使用的前置负担。
- 风险例外：无感不等于绕过审批。高风险、破坏性或超出授权范围的操作仍必须明确告知并取得许可。

### 跨阶段验收门

- 零配置基线：使用默认设置即可完成日常任务，用户不需要先理解状态机、记忆索引、恢复循环或内部任务书。
- 管理同源：设置页、记忆树和执行记录操作的必须是 agent 实际使用的运行时策略、索引与数据，不能用只影响展示的假开关代替。
- 自动留痕：会改变持久状态的自动行为必须记录原因、来源、作用域和结果，并能从对应管理入口追溯。
- 可逆优先：可恢复的行为提供恢复或撤销路径；不可逆、高风险或越权行为在执行前明确审批。
- 渐进披露：默认界面只呈现当前需要的信息，完整任务书、执行证据、记忆来源和高级策略按需展开，但关键风险与失败状态不得被隐藏。
- 自定义非负担：高级选项具有可靠默认值；用户不做任何额外配置时，核心能力仍完整、稳定且可预测。

## 记忆树核心架构约束

记忆树首先是运行时记忆系统；用户侧只提供简洁记忆文件页，不把底层结构映射成普通管理页面。

- 索引优先：常驻系统上下文只放轻量根索引和极少量不可缺失的核心规则，不把所有记忆分支预先展开。
- 分层延伸：根索引只描述一级分支；分支索引再描述子分支或叶节点。记忆规模增长时扩展下层索引，而不是让根提示词等比例变长。
- agent 主动介入：系统提示词明确告诉 agent 记忆树的存在、索引含义和查询方式。agent 根据当前任务沿索引选择需要的分支，再通过记忆工具把对应片段介入本轮上下文。
- 分支不是文件夹：每个分支同时定义来源、子索引、检索条件、注入预算、优先级和失效策略，是上下文介入的策略边界。
- T1/T2/T3 是被选中分支内部的内容优先级，不等于“启动时遍历所有分支并注入”。T1 可用于极小的必要规则或分支摘要，T2 在分支被激活后按相关性返回，T3 只在进一步搜索时返回。
- 上下文防膨胀：每次分支展开都有独立预算、去重和来源记录；未被索引命中的分支不进入上下文，过大的结果继续返回下一级索引或摘要，而不是整棵树展开。
- 写入同构：agent 写入记忆时也必须沿同一索引确定目标分支、父节点、作用域和层级；新记忆不能绕过树结构直接平铺到某个文件。
- 自动整理：写入后同步更新父级索引摘要和检索键，并根据重复度、重要性与作用域执行去重、合并建议或层级调整，使读取索引始终能反映真实记忆结构。
- 来源可追溯：每个注入片段保留 branch、source、tier、生成时间和命中原因，供 agent 判断可信度，也供 UI 解释。
- 视图边界：用户记忆页直接读取活动数据根中的六份权威文件，不另造展示副本；Runtime 的分支、索引、Atom 和来源只通过内部治理能力管理。

## 阶段 1：澄清契约一等化

目标：让“不清楚就问”成为清晰状态，而不是靠 `lastError` 伪装成错误。

工作项：

1. 新增或标准化 `ClarificationRequest` 数据结构。
2. DECIDE 在关键信息缺失时输出明确的问题、缺失字段、可选默认值和阻塞原因。
3. ASK_USER 使用 `ClarificationRequest` 生成用户可直接回答的问题。
4. 保存澄清请求与用户回答，作为本轮任务上下文的一部分。
5. 区分两种情况：
   - 闲聊或轻微模糊：直接自然回复。
   - 执行任务缺关键决策：进入 ASK_USER。

验收标准：

- 缺少目标路径、权限范围、供应商密钥、删除/覆盖确认等关键信息时，LS 不猜测执行。
- ASK_USER 的问题具体、可回答，不把规划负担丢给用户。
- 简单任务不会因为轻微模糊而过度追问。

实现状态：已完成（2026-07-10）。

- 新增可序列化的 `ClarificationRequest` / `ClarificationResponse`，覆盖缺失信息、真正不清晰的输入和故障升级。
- DECIDE 缺少关键信息时不再写入 `lastError`，而是生成带缺失字段、阻塞原因、问题、选项和安全默认值的澄清请求。
- ASK_USER 确定性渲染结构化问题，不再额外调用一次模型改写，因此不会漏问必答字段，也减少一次等待。
- 真正 `unclear` 的输入进入 ASK_USER；普通闲聊、上下文续答和轻微模糊仍由 classifier 归入 chat 后自然回复。
- 澄清请求写入 assistant 会话消息；紧随其后的用户回答自动关联 request id，并同时进入执行日志与 run result。
- 澄清契约、会话关联和分类分流均有定向回归保护；当前全仓验证结果见 [项目状态](../decision/project-status.md)。

## 阶段 2：局部重规划与步骤级恢复

目标：任务失败时只修失败处，不把已完成的工作推倒重来。

工作项：

1. VERIFY 输出失败或未完成的具体 step id。
2. DECIDE 支持基于 `verifyFeedback` 只改写失败或未完成步骤。
3. EXECUTE 能从指定步骤继续执行，保留已完成步骤的证据和产物。
4. 工具错误、权限拒绝、文件不存在、模型调用失败分别进入不同恢复分支。
5. 记录每次重规划的原因、变更范围和重试次数。

验收标准：

- 多步骤任务中第 3 步失败时，第 1-2 步不会重复执行。
- 重规划不会悄悄扩大用户需求范围。
- 超过重试上限时，LS 说明已完成部分、失败原因和需要用户决策的点。

实现状态：已完成（2026-07-10）。

- VERIFY 输出并校验具体 `failedStepIds`，形成 `PartialReplanRequest` 和可持久化的重规划历史。
- DECIDE 的局部合并由代码锁定范围：只接受目标步骤修改，原目标、验收标准、范围上限和已完成步骤不能被模型覆盖。
- EXECUTE 断点续跑并保留已完成步骤、工具证据与 attempt 次数；失败步骤重试时不重复执行完成步骤。
- 步骤失败区分工具错误、权限拒绝、路径不存在、模型错误、验证缺口、中断和未知错误。
- VERIFY 的模型误判、网络失败或 JSON 失败不能覆盖结构化失败证据；已知未完成任务会继续局部重规划或进入恢复。
- 两次自动局部重规划耗尽后进入 ASK_USER，不再用“强制通过”制造虚假成功。
- 重规划请求、保留步骤、修改步骤、决策时间和恢复时间随 task execution 写入执行日志。
- 局部重规划、断点续跑、重试上限和执行日志均有定向回归保护；当前全仓验证结果见 [项目状态](../decision/project-status.md)。

## 阶段 3：记忆树运行时注入与写入闸门

目标：让记忆树真正介入每次 run 的上下文构建，同时让 LS 学会东西但不把噪音写进长期记忆。

工作项：

1. 在 runner 基础设施中构建唯一的 `MemoryTree` 实例，并注册可用分支；写入后的缓存失效也回到同一实例。
2. 为系统提示词生成稳定、定长优先的根索引，说明一级分支用途、何时展开和可用检索工具，使 agent 具备“我有一棵可按需查询的记忆树”的明确概念。
3. 将当前“遍历分支后统一注入”的接口重构为索引优先协议：提供根索引、分支索引、按 branch/node/query 展开和选定分支内深搜四类能力，并由运行时代码拒绝跳级调用。
4. 将近期 daily prelude 从固定全量入口降为记忆树中的一个分支；只有极小必要摘要可常驻，其余内容由 agent 根据索引按需加载。
5. 增加本轮记忆介入账本：记录已展开分支、查询、片段、token 预算和去重键，避免同一 run 反复注入或无限沿树展开。
6. 注入结果保留来源、tier 和命中依据，经过现有安全信封后再进入模型上下文；单个分支失败时降级，不阻断整个 run。
7. 当分支结果超过预算时优先返回摘要和下一级索引，由 agent 决定是否继续深入，不能直接截入整批原文。
8. 定义结构化 `MemoryWriteIntent`：至少包含目标 branch、parent node、scope、tier、摘要、检索键、来源 run、置信度和写入理由。
9. 写入服务先通过树索引解析目标位置，再原子更新叶节点与父级索引；解析失败时进入可恢复队列，不能生成无法被索引访问的孤立记忆。
10. 增加自动整理规则：写入前查重，写入后刷新父级摘要；对高度重复内容合并或建立引用，对作用域变化提供提升/降级记录。
11. 明确四类持久信息：
   - 每日流水：细节记录，便于回溯。
   - 长期记忆：稳定、跨项目、长期有用的事实和偏好。
   - 项目记忆：只对某个项目或工作区有效的事实、约定、目录知识。
   - 经验库：可复用的方法、失败教训、工具使用模式。
12. 为每类写入增加 `importance`、`confidence`、`scope`、`sourceRunId` 和 `reason`。
13. EVOLVE / CAPTURE 区分“记录过程”和“沉淀能力”。
14. 对低置信、重复、临时、情绪化、仅本轮有效的信息拒绝写入长期记忆。
15. 支持从执行结果中提炼经验，但需要去重和降噪。
16. 记忆写入采用自动模式，不逐次请求用户确认；底层写入必须内部可审计、可失效、恢复或重建，普通 GUI 不展示 Atom。
17. 经验写入默认使用平衡阈值，并允许用户在设置中调整；阈值调整只影响后续判断，不静默改写历史记忆。

验收标准：

- 日常流水可以详细，长期记忆必须克制。
- 用户明确偏好、项目规则、可复用工具经验能进入正确分支。
- 记忆树 UI 后续能解释“这条记忆为什么被写入”。
- agent 能从系统上下文中的根索引选择分支，并在运行过程中按需展开到足够深度，而不是依赖启动时预装全部相关记忆。
- agent 检索时遵循“根索引 → 分支索引 → 节点/查询展开”；只有索引展开不足时才可在同一分支内深搜，不能默认跨树或直接进入向量库。
- 记忆总量增长不会让每轮基础系统上下文等比例增长。
- 当前 run 的每次记忆介入都可追溯到具体索引、分支、查询和来源，并受模型上下文预算约束。
- 自动写入的每条记忆都能从根索引沿父子关系访问；不存在“文件里有内容，但树索引找不到”的孤立记录。
- 写入同类记忆时能复用、合并或更新现有节点，不靠无限追加制造重复上下文。

实现状态：行为/权限拆分已完成；逻辑容器边界与终端复核于 2026-07-18 完成基础闭环。

- Runner 只构建一个 `MemoryTree`、`MemoryRepository` 和 `MemoryWriteService`；系统提示词、读取工具、运行账本、自动写入与缓存失效共用该实例。
- 旧 `inject()` 全树遍历协议已删除，替换为稳定根索引、分支索引、按 branch/node/query 展开和选定分支内深搜；运行时强制同一 run 先成功读取分支索引、再展开，之后才允许深搜该分支。
- `memory_search` 已降为只读兼容导航器：未指定分支只返回根索引，指定分支只返回分支索引，永不直接返回记忆正文。
- `MEMORY.md` 不再作为 bootstrap 注入，近期 daily prelude 不再每轮加载；旧 `MEMORY.md`、daily、experience、project/git 和向量记录保留为只读兼容来源。结构化/文件来源可由索引展开，向量来源只在已导航分支的深搜阶段作为兜底候选。
- 每轮账本保存根索引、分支、查询、片段 id、来源、tier、命中原因、预算、去重键和降级错误，并写入 execution log；单分支失败不阻断其他分支。
- 超预算内容不再截入半段原文，而是返回可继续定位的摘要索引；分支内深搜仍受总预算、分支预算、结果上限和同一 run 去重约束。
- 自动写入使用结构化 `MemoryWriteIntent`，原子树文档同时保存叶节点、父子索引、审计和恢复队列；缺失父节点不会产生孤立记忆。
- 写入闸门覆盖写侧安全校验、长期/项目/经验阈值、临时与情绪状态拒绝、作用域约束、精确去重、相似合并、来源强化、父摘要刷新以及提升/降级和归档状态的数据能力。
- EVOLVE 只沉淀长期/项目/经验能力，CAPTURE 只记录 workspace-scoped daily 流水；旧自由文本 notes 不再绕过结构化闸门。
- 设置中的记忆树概览已改读真实运行时四分支和同一原子仓库，不再展示伪造的“深度检索分支”；经验学习阈值默认 0.65，可在设置中调整且只影响后续写入。

- 索引协议、预算、去重、失败降级、结构化写入和 Runner 持久化均有定向回归保护；当前全仓验证结果见 [项目状态](../decision/project-status.md)。

## 阶段 4：TaskBook 持久化与过程 UI 对齐

目标：关闭应用再打开后，仍能看到同一套无气泡的 agent 执行过程，而不是退回简单对话框。

工作项：

1. 持久化 task book、步骤状态、工具调用摘要、验证结果和最终回复之间的关联。
2. 历史消息加载时，统一渲染为 live 过程 UI 的同一套结构。
3. 正在执行的步骤和命令保留稳定周期的弧光效果。
4. 默认折叠命令细节；用户可手动展开。
5. 任务完成后自动折叠过程，只保留结果摘要；用户仍可展开查看过程。
6. 在输入栏上方增加独立的执行进度圆环：空闲时不占据视觉注意力，执行中显示当前完成比例。
7. 光标悬浮或键盘聚焦执行进度圆环时，展开当前任务书、活动步骤和实时进度；离开后按统一浮层规则收回。
8. 执行进度圆环与输入栏内已有的上下文占用圆环保持独立：前者表示任务步骤进度，后者只表示供应商返回的真实上下文占用。

验收标准：

- 只有用户消息使用对话气泡；agent 回复和执行过程不使用气泡。
- 实时过程和重启后的历史过程视觉语言一致。
- 长命令输出不会把主对话区撑乱。
- 简单任务只显示简洁过程；标准和复杂任务可从进度浮层展开完整 task book。
- 进度浮层遵守统一的悬浮延迟、切换、淡入淡出、外部点击收回和层级规则。

实现状态：已完成（2026-07-11）。

- `ExecutionLog` 持久化 `TaskBook`、步骤执行结果、工具调用、全部验证记录和最终回复；任务书中的运行时 `stageResults` 不重复写入持久层。
- 历史加载按消息实际引用的 run id 读取执行日志，并通过共享转换恢复完整过程；同一 run 的过程只挂载到最终 assistant 消息，默认折叠，不会在中间工具消息上重复出现。
- 实时过程与历史过程统一使用无气泡的 `AssistantTurnMessage`、步骤时间线、验证时间线和命令折叠项；只有用户消息保留对话气泡。
- 任务执行中保持过程展开；完成、失败或中断后自动折叠，只保留最终结果，用户仍可重新展开。命令详情默认折叠并限制输出高度，避免长输出撑乱主对话区。
- 正在执行、验证或运行中的命令统一使用 2.8 秒稳定周期的文字弧光，不使用随机闪烁。
- 输入栏上方的任务进度圆环由真实 task step 状态计算，规划/执行/验证/完成状态明确；完成后短暂停留并平滑退出，空闲时不占视觉注意力。
- 进度浮层首次悬浮等待 0.5 秒，键盘聚焦或点击立即展开，支持移出、外部点击和 Escape 收回；浮层显示完整任务书步骤和当前进度。
- 任务进度圆环与输入栏内的上下文占用圆环完全独立。上下文圆环按可用真实性来源显示 Provider usage 或匹配具体模型 tokenizer 的本地精确 `ContextSnapshot`，并明确区分两者；tokenizer 不可用时不进行字符换算，任何情况下都不能用任务进度或无来源估算冒充真实占用。完整演进契约见 [Agent Runtime 连续性任务书 2026-07-14](agent-runtime-continuity-taskbook-2026-07-14.md)。
- 持久化、历史重建、事件顺序、局部重规划最终流和进度计算均有回归保护；当前全仓验证结果见 [项目状态](../decision/project-status.md)。

## 阶段 5：权限模式与系统提示词拆分

目标：把“agent 行为模式”和“权限模式”彻底分开。

工作项：

1. 系统提示词模式：
   - 通用：适合绝大部分任务。
   - 编程：为代码阅读、修改、测试、终端使用和项目维护特化。
2. 权限模式：
   - 完全访问：LS 逻辑容器内的读、写、改、删和执行免批准；容器外或范围不明的任何操作仍需批准。
   - 研究：容器内只读免批准；写、改、删、执行以及容器外或范围不明的任何操作需要临时批准。
   - 受限：所有工具操作都需要明确批准，包括容器内读取。
3. 权限模式不改变 agent 的思考方式，只改变工具是否允许执行。
4. 权限弹窗支持一次性批准、会话级批准或拒绝。
5. 默认批准粒度为单次操作；用户可在弹窗中将同类操作授权扩展到当前会话，但不默认形成永久项目信任。
6. 逻辑容器根是活动完整应用数据根 `<data-root>`，默认名为 `.littlesheep`；`workplace/` 是其默认工作区子目录。当前实现是 Main 进程路径闸门，不冒充真实 Docker/OS 沙箱。
7. Agent 工具与内置终端共享边界判定；动态 Shell、网络、外部进程、符号链接越界和无法证明范围的调用按 `unknown` 请求批准。核心源码只读边界高于所有模式。

验收标准：

- 选择“研究/受限”不会让 agent 变笨或改变任务拆解方式。
- 需要权限时，弹窗说明风险、作用范围和可选批准级别。
- 用户手动终端命令和 agent 工具命令权限边界清晰。

实现状态：已完成（2026-07-11）。

- 新增独立的通用/编程 `AgentProfile`。通用配置保持领域中立并按任务比例规划；编程配置强化代码阅读、修改、测试、终端和工程交付。两套提示词都明确不能授予工具权限。
- 行为配置由运行时配置和单次 run 共同解析，并进入 DECIDE、EXECUTE、REPLY、RECOVER、VERIFY 与多步骤最终回复装配；定向回归用独立 sentinel 证明规划、执行和验证不会丢失当前配置。
- 设置页新增“Agent 行为”控制面，通用/编程选择写入 agent 实际使用的运行时配置；输入栏只保留完全访问、研究、受限三种权限模式，两套选择互不替代。
- 权限模式只生成工具批准策略，不携带系统提示词或模式专属超时：完全访问仅自动批准容器内工具；研究仅自动批准容器内只读工具；受限为所有工具请求批准。三档对容器外和范围不明的访问都必须询问。
- Electron Main、Runner、Harness、内置文件工具和 PTY/PowerShell 终端已经传递并复核 `containerRoot`、`permissionMode` 与单次批准结果；Renderer 只负责交互，不能覆盖 Main 的边界结论。
- 外部工作区不会因为用户选中而进入容器；Agent run 在外部或未知工作区启动时，Runner 先跳过自动资源/文档扫描，待明确访问批准后才继续。用户主动的预览、编辑和保存属于独立 UI 操作路径。
- 旧 `coding` 模式迁移为“编程行为 + 研究权限”，不再因历史兼容值意外获得完全访问。旧 `info` / `physical` 仍分别迁移到完全访问 / 受限。
- 审批弹层明确显示发起来源、权限模式、操作风险和参数，提供“拒绝 / 本对话允许 / 仅本次”，并默认聚焦“仅本次”。弹层使用共享 220ms 双向 presence，不再在决策后突然消失。
- “仅本次”不在同一 run 内缓存复用；相同操作再次发生仍重新询问。“本对话允许”只按 conversation + source + operation type 保存于内存，草稿会话首次落盘后迁移到真实 session id，废弃草稿、归档/删除单会话或应用重启不会形成永久项目信任。
- Agent 工具调用使用 `source=agent`，用户在拓展工作区发起的保存/终端使用 `source=workspace`；两者即使 action 相同也不能共享授权。无批准通道时受保护工具 fail closed。
- 行为/权限正交、审批粒度、来源隔离和重启失效均有定向回归保护；当前全仓验证结果见 [项目状态](../decision/project-status.md)。

## 历史阶段 6：Atom 管理控制面原型（已退役）

该阶段曾验证 Renderer 直接读取 Runtime 分支、节点、来源、D2/D3、命中账本和管理操作，证明底层数据真实可治理。2026-07-16 的产品边界决定不再把这些内部结构展示给普通用户：

- 当前记忆页只列出 `AGENTS.md`、`SOUL.md`、`USER.md`、`PHILOSOPHY.md`、`TOOLS.md` 和 `MEMORY.md`；
- 当前仅 `SOUL.md` 可直接编辑，写权限由 Main/Local App API 强制校验；
- Runtime 仍保留 Atom 的移动、合并、失效、恢复、重建和证据导出能力，并继续使用同一 Memory Repository；
- LLM 只预载记忆树简介与根索引，再按需进入分支和 Atom；
- 用户需要深入了解 LS 时，由独立 Skill 解释或查阅仓库文档，不把底层治理面板重新铺回普通 GUI。

历史原型的测试与内部接口可以继续保护 Runtime 治理契约，但不再构成当前前端验收标准。

## 阶段 7：评测与回归套件

目标：防止核心能力越改越散。

工作项：

1. 增加核心场景回归：
   - 闲聊不进入复杂任务书。
   - 简单读取/解释任务不过度规划。
   - 复杂任务必须生成 task book。
   - 关键信息缺失进入 ASK_USER。
   - 中间步骤失败时触发局部重规划。
   - 低价值信息不进入长期记忆。
2. 为 DECIDE / EXECUTE / VERIFY / EVOLVE / CAPTURE 增加或补齐单元测试。
3. 为历史执行过程恢复增加 UI 或数据层测试。

验收标准：

- 核心流程改动必须有回归保护。
- 测试能覆盖“别过度做”和“别失忆”两个方向。

实现状态：已完成（2026-07-11）。

- 新增独立核心评测入口 `pnpm test:core-eval`，将需求校准、步骤执行、验证、学习、每日捕获和历史过程恢复收束为一个稳定回归门。
- 新增场景级核心契约：闲聊绕过 DECIDE/TaskBook；简单读取和解释任务由代码压缩为一个与校准目标一致的轻量步骤；标准/复杂任务不能被模型关闭 TaskBook；缺关键字段稳定进入 ASK_USER。
- 中间步骤失败场景验证只修改失败步骤、保留完成步骤证据并从断点续跑；自动局部重规划不会重跑已完成工作。
- “别失忆”场景同时验证低价值长期记忆被写入闸门拒绝、真实项目规则进入 workspace 分支、根索引不预载全文、agent 按分支索引再展开所需记忆。
- 历史过程恢复已抽成共享纯数据转换；执行日志经过 JSON 落盘和重读后，仍能恢复步骤、工具调用、状态、耗时和默认折叠状态。
- 同一 run 的中间 `assistant tool_calls` 不再重复挂载整套过程；过程只归属最终 assistant 消息。历史加载只读取当前会话实际引用的 run，避免随全局日志增长而退化。
- 独立核心评测覆盖 DECIDE / EXECUTE / VERIFY / EVOLVE / CAPTURE、跨阶段 Core Flow 和历史恢复数据链；当前测试数量只在 [项目状态](../decision/project-status.md) 维护。

## 已确认决策

- 记忆自动写入；用户通过记忆文件页管理高层资源，底层写入必须在 Runtime 内可追溯、可失效、恢复或重建。
- 失败步骤自动局部重规划，最多尝试 2 次。
- 权限审批默认仅对当次操作有效，可选择在当前会话允许同类操作。
- 简单任务显示简洁过程，标准或复杂任务可展开完整 TaskBook；输入栏上方的执行进度圆环在悬浮时展示实时步骤和进度。
- Atom 的归档、失效、提升和降级属于内部治理能力，关键操作保持权限与审计闸门，不在普通 GUI 中铺开。
- 经验学习采用平衡阈值，并在设置中提供可调选项。
- 实施顺序遵循本任务书的阶段依赖关系。
