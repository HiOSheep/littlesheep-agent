# LittleSheep Agent 核心与记忆系统任务书 2026-07-14

最后更新：2026-07-16 19:51:41
版本：v2.0
状态：执行基线

> 2026-07-16 边界更新：本任务书中“用户直接查看、修改、停用或恢复 Atom”的旧管理页方案已被替代。普通 GUI 只展示六份记忆文件并仅允许编辑 `SOUL.md`；Atom、关系、向量和审计由 Runtime 内部治理。LLM 仍通过根索引按需访问完整记忆树。以下旧阶段记录只作为历史背景，不再指导前端实现。

## 1. 目标

在暂停非必要 UI 扩张的前提下，把 LittleSheep 从“能力较完整的本地 Agent 原型”推进为可以被真实任务验证的核心系统：

- 准确判断用户需求和任务复杂度，避免“大炮打蚊子”；
- 对复杂任务进行可恢复、可验证、可追踪的执行；
- 让记忆树成为上下文中的索引注册表，按索引精准注入记忆，避免上下文膨胀；
- 自动整理可复用记忆，同时通过简洁记忆文件视图保留用户对人格等高层资源的控制；底层 Atom 治理保持内部可审计、可恢复；
- 在真实供应商、长任务和重启场景中证明“不失忆、高效完成任务”。

## 2. 范围规则

### 本阶段允许

- 修复阻断 Agent、记忆、权限、会话恢复和数据安全的 Bug；
- 完成 Agent 核心闭环和记忆树闭环；
- 为核心行为补充测试、运行账本和真实场景验收；
- 修改 UI 以修复核心信息不可见、状态错误或操作无法完成的问题；
- 触及热点文件时进行局部、可验证的职责抽取。

### 本阶段暂缓

- 非阻断性的视觉细节、动效和布局继续扩展；
- 新增 MCP、渠道、插件类型和 IDE 能力；
- 为减少行数而进行的全仓重构；
- 没有真实场景和验收标准支撑的“完整化”功能。

## 3. 当前基线

已具备但仍需真实场景验证的能力：

- Harness 驱动的 `CLASSIFY → DECIDE → EXECUTE → VERIFY → RECOVER → FINALIZE`；
- TaskBook、步骤状态、工具调用记录和执行证据；
- 权限模式与行为模式分离；
- `root index → branch index → expand → branch-scoped deep search` 的记忆导航约束；
- 记忆树注册、项目记忆投影、归档、恢复和简洁记忆文件界面；
- 版本化会话摘要和非破坏性压缩基础；
- Context Engine 的候选上下文、附件清单、摘要记忆和安全估算基础；
- Electron 本地应用、流式对话、工作区和外部渠道基础；
- 仓库质量门、类型检查和自动化测试。

当前验证结果统一以 [项目状态](../decision/project-status.md) 为准，本任务书不复制会快速过期的测试数量。工程质量门通过仍不等同于生产就绪：真实供应商、长任务、活动 run 重启续跑、MCP、打包发布和完整用户场景尚未全部闭环。

## 4. 执行阶段

### 阶段 A：建立可追踪基线

任务：

1. 固定当前源码、测试、构建和仓库卫生结果；
2. 把现有问题分为 P0 阻断、P1 核心能力、P2 体验和长期设想；
3. 为每个 P0/P1 问题补充复现步骤、根因、影响范围和回归测试；
4. 形成可理解的提交边界，禁止把核心重构、UI 调整和文档治理混在同一提交中。

验收：任何核心回归都能定位到具体模块、测试和提交；用户数据不被纳入仓库。

### 阶段 B：完成 Agent 任务闭环

重点模块：`packages/harness/`、`packages/runner/`、`packages/context/`、`packages/tools/`、`packages/safety/`。

任务：

1. 简单任务走轻量路径，不强制生成完整 TaskBook；
2. 复杂任务必须包含目标、步骤、验收标准、工具、产物和失败策略；
3. EXECUTE 按步骤执行，记录 `step_start/tool_start/tool_end/step_done`；
4. VERIFY 按步骤验收，不用最终回复掩盖未完成步骤；
5. 失败只重试失败步骤，保留已经完成的产物和证据；
6. 权限拒绝、用户中断、模型失败、工具失败、路径错误和验证失败必须分类；
7. FINALIZE 明确成功、部分完成、失败、中断和待用户决定；
8. 长任务支持有限重试、检查点和防止重复副作用。

核心验收场景：

- 简单文件查询或说明任务不会被过度规划；
- 多步骤文件修改任务能逐步执行并验证；
- 中途工具失败后只恢复失败步骤；
- 用户拒绝权限后不会绕过权限继续执行；
- 中断和重启后不会伪造成功或重复执行已完成动作。

### 阶段 C：完成记忆树闭环

重点模块：`packages/memory-tree/`、`packages/memory-core/`、`packages/context/`、`packages/prompt/`。

任务：

1. 根索引常驻上下文，具体分支按需求逐级展开；
2. 默认禁止跨树向量召回，向量搜索只能作为已导航分支内的兜底；
3. 每次记忆介入记录 branch、source、tier、命中原因、预算和去重结果；
4. 用户偏好、项目事实、任务经验和运行流水分开存储；
5. 自动写入必须沿索引确定 parent、scope、tier、来源和理由；
6. 重复记忆合并或提升已有节点，不无限追加；
7. 记忆更新支持版本、审计、停用、归档、恢复和冲突提示；
8. 记忆蒸馏只能写入结构化、可回滚的记忆树，不得直接把模型原文当长期记忆；
9. 重启后沿同一索引恢复关键记忆，不依赖内存缓存。

核心验收场景：

- 跨会话找回用户偏好；
- 项目记忆不污染其他项目和独立对话；
- 未命中的分支不进入上下文；
- 同一事实重复写入后不会无限膨胀；
- 用户能在记忆页查看当前六份记忆文件并编辑 `SOUL.md`；Atom 的定位、停用和恢复由 Runtime 内部维护流程完成；
- 记忆冲突不会被静默覆盖。

### 阶段 D：上下文、会话和真实模型验收

任务：

1. 对 OpenAI、DeepSeek、GLM 各完成最小真实请求；
2. 验证普通对话、工具调用、中断、失败和长任务；
3. 按具体模型适配上下文上限、reasoning 参数和 usage 字段；
4. 只有供应商返回真实 usage 时才显示真实占用，估算值不得伪装成真实值；
5. 验证摘要压缩后关键目标、约束、产物和记忆索引仍可恢复；
6. 验证应用重启后会话、执行日志、摘要和记忆仍可继续；
7. 记录模型、配置、成本、耗时、失败原因和验收结论。

验收：每个供应商至少有一份可复现报告；报告明确区分配置层通过、连接器层通过和真实任务通过。

### 阶段 E：有限度维护性收敛

原则：只在修改功能或修复 Bug 时拆分，不进行一次性全仓重构。

优先顺序：

1. 禁止继续向 `packages/app/src/renderer/App.tsx` 添加核心业务逻辑；
2. 按领域逐步抽取会话、项目、设置、工作区和记忆控制器；
3. 将 Local App API 按领域拆成 route/service，保留兼容入口；
4. 统一 main、renderer、runner 共享类型，避免重复定义；
5. 新 package 必须写明职责、依赖方向、入口、测试位置和不放入现有包的理由；
6. 每次抽取必须保持行为不变，并附带定向测试和完整 typecheck。

## 5. 完成门槛

在以下条件满足前，不恢复非必要 UI 扩张：

- P0 Bug 为零；
- Agent 三类核心场景通过；
- 记忆树五类核心场景通过；
- 至少三家供应商完成真实请求验收；
- 长任务压缩、失败恢复和重启续跑通过；
- `check:repo`、`test`、`typecheck`、`build` 和应用恢复检查通过；
- 所有结论都有测试、运行账本或真实场景证据；
- 文档与源码状态一致。

## 6. 每项任务的工作格式

执行任何新任务时，先记录：

```text
目标：
影响范围：
复杂度：简单 / 标准 / 复杂
涉及模块：
验收标准：
失败与恢复策略：
是否需要真实模型：
是否涉及用户数据：
```

完成后记录：

```text
实现结果：
测试结果：
真实场景结果：
遗留问题：
文档更新：
```

## 7. 明确不做的事

- 不把 UI 完整度当作 Agent 能力完成度；
- 不为了降低文件行数进行无证据的大重构；
- 不把本地估算的 token 数显示为真实 usage；
- 不把一次运行细节自动提升为长期记忆；
- 不用向量召回替代记忆树索引导航；
- 不把用户数据、API key、测试缓存和构建产物提交到仓库；
- 不在没有验收标准的情况下新增能力模块。

## 8. 后续决策点

以下事项暂不进入当前执行阶段：

- MCP 客户端的具体协议和权限策略；
- 插件 API v2；
- 完整 IDE、终端和工作区产品化；
- 安装包、升级、卸载和发布回滚；
- 下一轮 UI 视觉打磨。

它们必须等核心任务闭环、记忆闭环和真实供应商验收完成后重新评估。
