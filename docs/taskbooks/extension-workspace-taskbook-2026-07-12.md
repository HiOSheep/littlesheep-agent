## 目标

把 LS 从“单一对话应用”推进为“对话 + 可执行工作现场”的本地 agent 工作台。右侧拓展工作区用于承载文件、终端、编辑器、预览和 agent 阶段产物；主对话区继续负责需求输入、过程可见和结果沉淀。

## 设计边界

- 左侧栏负责项目、对话、记忆树和设置入口。
- 主对话区负责用户需求、agent 执行过程、结果摘要。
- 右侧拓展工作区负责打开和管理工作现场，不替代主对话。
- 左侧栏与核心工作区相互独立。核心工作区内部由主对话区和拓展工作区两个同级子区组成；拓展工作区展开、全屏或折叠只影响主对话区，不影响左侧栏。
- 拓展工作区必须可折叠、可调整宽度、可全屏展开，且有平滑过渡；动效时长和侧边栏折叠统一使用 320ms。分隔线左右拖动都采用两层阈值：第一层停止压缩并进入仅光标移动的缓冲区，第二层为第一层的一半，越过后才折叠对应区域；反向越过时原路反播同一动画。完全折叠后不保留实体侧轨或纵向线条，也不占用对话区宽度；对话区右上角保留固定的紧凑展开按钮，核心区最右侧整条区域另作为不拦截底层控件的透明感应带，悬浮任意高度时在中部淡入第二个恢复图标，并与用户消息保持稳定间距。
- 拓展工作区展开、折叠、全屏、活动标签和文件导航器状态都作为普通全局历史快照记录。进入全屏后的上一快照通常是非全屏状态，因此返回键会自然退出全屏；不得另写一条绕过历史栈的“优先退出”分支。
- 拓展工作区顶部是功能标签栏，不是固定静态标题。用户可以通过加号菜单新增“审查、产物、终端、浏览器、侧边聊天”等功能标签；从右侧文件管理打开的具体文件也会成为顶部标签。点击标签切换内容，关闭标签后回到相邻标签；关闭最后一个标签时保留面板并显示快捷启动空态，不自动折叠。
- 产物管理是拓展工作区的一等标签页，负责项目级成果回看、筛选和重新打开，不应被埋在对话消息里。
- agent 执行过程和历史执行记录必须使用同一套无框折叠过程 UI。正在执行时过程可见，完成后自动折叠只保留结果；用户可手动展开指令、执行过程和单条命令细节。
- 拓展工作区内部的文件管理是右侧覆盖式文件定位器，不等同于顶部功能标签，也不参与拓展工作区的宽度计算。顶部标签负责打开的工作内容，右侧文件管理负责快速定位当前工作区文件；文件管理栏可折叠为窄图标入口，折叠状态需持久化。从文件管理打开文件时，必须创建或激活顶部文件标签，而不是只在文件管理页内替换预览内容。
- 先把 Monaco 做成 LS 的内置 VS Code 风格代码工作台：代码、脚本、配置、锁文件和可识别文本默认在 LS 内打开，直接提供语法高亮、行号、只读/编辑和保存；图片/PDF 走预览，Word/PPT/Excel 等 Office 文件保持文件卡片和系统默认应用入口。完整 VS Code Extension Host 另列后续评估，不把外部 VS Code 伪装成内嵌。
- 重启后应恢复当前项目、最后打开的对话、工作区布局状态和可从历史执行记录重建的产物入口。
- 终端的运行时版本由设置中的开发环境管理页决定；工作区终端只接收 Main 派生的已验证工具链环境，不直接修改宿主 `PATH`。当前除 Electron 内置 Node 外，其他工具链仍需先导入，不能把“检测到系统版本”写成“LS 已内置”。
- 显式切换项目、工作区或带工作区的历史对话时，右侧拓展工作区必须和新工作根对齐；不属于新工作根的临时打开请求、文件标签和未保存草稿不能继续占据当前工作现场。

## 阶段 1：拓展工作区基础壳层

状态：已实现壳层与标签模型。审查、产物、终端、文件标签和内置浏览器已有基础实际内容；浏览器支持 HTTP(S) 预览、内部导航、独立有界前进/后退和刷新；“侧边聊天”仍是占位工作面，不属于已完成能力。

验收标准：
- 右侧出现拓展工作区面板，和主对话并列。
- 面板可折叠/展开，可拖拽调整宽度，有最大/最小宽度。
- 支持全屏展开，主对话区通过滑动/遮盖式过渡让位，工作区边缘应有可见移动边界，而不是生硬跳变或瞬间消失。
- 面板内有可增删、可切换的功能标签栏：审查、产物、终端、浏览器、侧边聊天和已打开的具体文件。
- 产物标签页可从加号菜单打开，并可像其他标签一样关闭、恢复和持久化。
- 文件管理以右侧覆盖层呈现，可折叠或展开，可筛选文件，收起后保留窄图标入口。
- 从文件管理打开文件会创建顶部文件标签；文件预览、编辑、保存、外部打开都发生在对应文件标签中。
- 当前项目/默认工作区能在概览里显示。
- 审查页应显示工作现场恢复摘要，包括当前标签、打开文件、产物索引、终端活动和未保存草稿状态，让用户重启后能确认现场是否连续。
- 宽度、折叠、全屏、当前标签页、打开的标签集合能持久化。
- 重启后会尝试恢复最后打开的对话；如果对话已被归档或删除，则清理本地指针。
- 切换到项目或项目对话后，右侧工作区根目录应随之对齐，避免仍显示上一个项目的文件标签。

## 阶段 2：文件树和基础预览

状态：已实现基础形态。文件树是拓展工作区内独立的右侧覆盖式文件管理栏，不再占用一个顶部“文件管理”标签；它支持折叠、筛选、刷新和外部 VS Code 打开，并覆盖在功能标签或具体文件标签右侧。从文件管理打开文件会创建顶部文件标签。文本、代码、脚本、配置、锁文件和 Markdown 默认在 LS 内置 VS Code 风格编辑器中打开；图片和 PDF 用内置预览；Word/PPT/Excel 等 Office 文件保持文件卡片和系统默认应用入口。

验收标准：
- 文件管理栏展示当前工作区文件树，覆盖在工作内容右侧，并可折叠为窄图标入口。
- 点击文件会创建或激活顶部文件标签，文件内容不直接替换文件管理栏自身。
- 打开具体文件或切换其他功能标签后，右侧文件管理栏仍可覆盖显示和折叠，用户不需要切换工作面就能继续定位文件。
- 点击文本/Markdown/图片/PDF 等文件能在工作区预览或打开对应标签。
- 点击代码、脚本、配置、锁文件和其他可识别文本文件时，默认进入 LS 内置 VS Code 风格编辑器标签，而不是直接调用系统默认应用。
- Word/PPT/Excel 等 Office 文件显示文件卡片并提供系统默认应用或外部 VS Code 打开入口。
- 对话里的附件可点击在拓展工作区打开。
- 预览区显示路径面包屑；附件等非当前工作区文件以“临时预览”根目录打开，并提供回到当前工作区入口。
- 重启后恢复上次打开的预览根目录和文件路径。

实现约束：
- 文件树由 Local App API 读取当前工作区，跳过 `.git`、`node_modules`、`out`、`dist` 等重目录，避免打开大项目时卡顿。
- 只允许读取当前工作区内路径；符号链接先不追踪，避免越界预览。
- 文本预览有大小上限，超出时显示文件卡片并允许系统默认应用打开。

## 阶段 3：统一产物索引

状态：已起步并落地基础持久索引与项目级产物页。服务端会把 agent `write/edit` 成功写入的文件记录到用户数据目录中的 `<user-data>/workspace/artifacts.json`，也会把用户在内置编辑器里的手动保存记为工作区产物；该索引不写入用户选择的项目文件夹。对话结果仍显示实时轻量产物入口；审查页会合并当前消息产物与持久索引。拓展工作区新增“产物”标签页，可按项目/当前对话、来源、动作和搜索词筛选，点击后在右侧拓展工作区打开。历史对话加载时仍可回放执行日志并从工具记录重建产物入口，作为持久索引的补充。

验收标准：
- agent 生成或修改的文件以产物卡片形式出现在对话过程或结果中。
- 点击产物卡片可在右侧拓展工作区打开。
- 执行过程里的文件型工具调用（如 read/write/edit）应显示“打开文件”入口，用户可以从命令详情直接跳到对应文件标签。
- 旧格式历史消息中的 trace/toolCalls 也应转译为同一套折叠式历史执行过程：主过程默认折叠，工具命令逐条默认折叠，展开后仍保持无框过程语言。
- 阶段性产物可按 run/session/project 索引。
- 重启后仍能看到历史产物入口。
- 用户手动保存的文件也进入工作区活动，而不是只停留在编辑器状态里。
- 项目级产物页能按来源、动作和文本搜索筛选，并能一键重新打开文件。

后续细化：
- 将图片、报告、终端导出等非 write/edit 来源纳入统一索引。
- 增加文件类型、会话标题和运行批次维度筛选。

## 阶段 4：内置编辑器

状态：已实现基础可用形态。文件标签里的文本/Markdown/代码类文件默认用 Monaco 内置 VS Code 风格编辑器以只读方式打开，保留语法高亮、行号和代码滚动；点击“编辑”后进入可写模式。文件标签标题会标明“内置 VS Code”和识别到的语言。文件标签会显示未保存修改标记，切换到其他拓展工作区标签时会保留当前 draft，仍打开的脏文件标签会在应用重启后从本地有界缓存恢复草稿；关闭未保存文件前会弹出确认层；编辑器支持 Ctrl/Cmd+S 保存。保存时遵守权限策略：完全访问确认后容器内外文件均免逐次批准；研究/受限模式写入前弹出确认；保存接口只允许写当前工作区内的普通文本文件，并检测外部修改冲突。

验收标准：
- 接入 Monaco Editor。
- 代码/文本类文件默认进入 Monaco 只读代码视图，支持语法高亮；点击“编辑”后进入可编辑模式。
- 未保存文件在标签页显示脏标记，切换标签和重启应用后不丢仍打开标签的本地 draft，关闭脏标签前必须确认。
- 支持 Ctrl/Cmd+S 保存当前内置编辑器文件。
- 编辑保存必须走权限策略。
- 对当前项目文件的修改能被 agent 感知并进入过程记录。

后续细化：
- 提供 diff/冲突解决视图。
- 让 Agent 在后续 run 中通过受预算的项目活动来源感知相关手动保存记录，而不是把完整活动索引默认注入上下文。

## 阶段 5：终端

状态：已升级为 LS 内 PTY 优先的持续 PowerShell 会话。终端标签使用 xterm.js 承载输出，在当前工作区启动持续 shell；Windows 上优先通过 node-pty/ConPTY 启动，加载失败时回退到旧 spawn 会话，避免原生模块问题导致应用不可用。终端会话创建和每次命令提交都按同一权限策略复核：完全访问确认后对容器内外及范围不明命令免逐次批准，研究/受限按权限矩阵审批；终端输出通过 SSE 实时写入 xterm。PTY 模式下终端视口会随拓展工作区缩放和全屏状态真实 resize，并支持向当前会话发送 Ctrl+C；“重启”会停止当前 shell 并创建新会话。用户手动运行的命令会按 workspace/session 写入终端活动索引，重启后可在对应工作区看到最近命令；PTY 会话中的受控命令会捕获从提交到下一条命令、中断或关闭之间的输出摘要。危险命令硬拒绝不受权限模式影响。

验收标准：
- 接入 xterm.js。
- 终端 cwd 默认跟随当前工作区，并在 Windows 上优先启动 PowerShell。
- 终端会话创建和命令提交遵守逻辑容器边界、权限模式和审批策略；静态无法证明范围的命令按未知处理。
- agent 执行命令与用户手动终端区分记录。
- 用户手动命令按当前 workspace/session 持久化，最近命令可点击回填，并通过悬浮小简介查看 cwd、状态和输出摘要。
- PTY 会话命令不应只记录“已发送”；应尽量捕获可用输出摘要和持续时间，至少在下一条命令、中断或关闭时结算，保证工作区活动流重启后仍有可回看的现场信息。
- 终端输入支持方向键历史、Esc 清空输入、Ctrl/Cmd+L 清屏，Ctrl+C 中断和重启会话的语义必须清楚。

后续细化：
- 在不破坏权限模式的前提下，评估“完全直打终端”模式：需要明确权限开关、当前会话级授权和可见风险提示，不能让 raw input 绕过命令审批。
- 将终端活动索引并入统一的会话/项目活动时间线，和 agent 工具调用分开标记。

## 阶段 6：外部工具连接

状态：基础入口已实现。文件树顶部可用 VS Code 打开当前工作区；文件预览标题区可用 VS Code 打开当前文件；未支持内联预览的文件也提供 VS Code 和系统默认应用两个入口。

验收标准：
- 提供“用 VS Code 打开当前项目/当前文件”入口。
- 终端、编辑器、预览的入口保持统一标签页逻辑。
- 不把 LS 变成完整 IDE，但允许借力外部 IDE。

## 阶段 7：高级交互终端与重度 IDE 评估

状态：规划中。PTY/ConPTY 基础、Ctrl+C、resize 和 spawn 回退已在阶段 5 完成；本阶段不重复规划基础 PTY 接入。

验收标准：
- 若开放原始键盘直通或交互式程序，必须先定义显式开关、会话级授权、输入审计、中断和退出语义，不能绕过当前权限策略；受控命令提交路径继续作为可靠回退。
- 发布构建必须验证 node-pty/ConPTY 原生模块装载与普通 spawn 回退，任一路径失败都不能阻止 LS 启动。
- LS 内置编辑器继续使用 Monaco 作为默认轻量代码工作台；如需完整 VS Code 扩展生态，单独评估 VS Code Web/Extension Host 集成，而不是把外部 VS Code 伪装成已内嵌。
- 外部 VS Code 入口保留为明确动作，不能替代 LS 内置工作区的默认文件打开体验。

## 后续设计规范

- 新功能优先接入拓展工作区，不把主对话区塞满。
- 所有展开、折叠、切换、全屏都需要过渡动画。
- 默认状态尽量无框；悬浮和激活时出现浅灰背景。
- 可交互图标必须有小简介。
- 最多三层子菜单。
- 只有用户消息使用对话框；agent 回复和过程不使用气泡框。
- 左上角前进/后退是全局共用导航，不属于某个页面；所有新页面/设置子页/工作区视图如需进入历史，必须走同一套路由历史。没有可前进/后退目标时必须呈现明确禁用态，不能出现看起来可点但点击无响应。

## 后续验收重点

- 做一次人工或自动化的端到端重启验收：打开项目、打开文件标签、制造未保存草稿、运行终端命令、打开产物页、重启 LS，确认恢复摘要与实际标签/草稿/终端活动/产物一致。
- 后续 UI 批次继续保留主界面、设置、拓展工作区与窄窗口的截图级回归。
- “终端完整直打”尚未开放，当前仍使用受控命令提交栏，这是为了不绕过权限策略。
- Office 文件后续可以按需补预览，但当前阶段保持文件卡片和系统应用打开更稳。
- 当前实现成熟度、最近质量门和跨模块优先级只在 [项目状态](../decision/project-status.md) 维护，本任务书不复制测试数字或本机恢复诊断。
