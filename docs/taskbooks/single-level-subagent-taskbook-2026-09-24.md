# 单层子 Agent 与执行效率任务书 2026-09-24

最后更新：2026-09-24 14:24:07

状态：方案与任务清单；尚未实现子 Agent，尚未证明性能收益。所有实现项保持未完成。

## 1. 目标与范围

用户已确定：LS 支持子 Agent；子 Agent 作为主 Agent 的工具调用；子 Agent 不得再创建子 Agent；长期目标是高效执行任务。

本任务书将“高效”定义为：在交付质量与权限边界不退步的前提下，缩短完成任务的总时间，或减少总模型成本。子任务数量、并发数量和模型调用次数本身都不是成果。

建议分两阶段实施：

- **第一阶段（SA-00～SA-09）**：一个 `subagent` 工具接受有界任务批次，子任务复用现有工具循环，并行完成独立分析、受控检索、审查；只读子任务返回证据，主 Agent 负责综合判断与实际修改。这是本任务书选定的最小起点，不是用户要求永久限制为只读。
- **按证据扩展（SA-11、SA-10）**：先根据同步委派的测量决定是否需要主子同时工作，再根据真实写入瓶颈决定是否开放受控写入；两者独立判断，不因竞品支持就默认加入。

不新增 DECIDE、planner、TaskBook 执行器或通用 Agent 管理平台。Harness / Runner 仅为身份隔离、权限、预算、生命周期与证据等缺失硬约束做必要修改。主 Agent 仍在现有 `execute → verify → finalize` 路径内决定是否调用工具。

这些是各产品的官方文档事实；下一列为针对 LS 的判断，均不表示 LS 已实现。

| 产品与官方资料 | 子 Agent 设计事实 | 对 LS 任务书的启发 |

| [OpenAI Agents API](https://developers.openai.com/api/docs/guides/agents-api/multi-agent) 与 [Responses API](https://developers.openai.com/api/docs/guides/responses-multi-agent) | 独立上下文、并行任务、父 Agent 综合结果；提供创建、消息、等待、中断等协作动作，官方建议短任务及强依赖链留在主 Agent | LS 首版可先保持工具调用形态；若测量发现父等待占主导，再补主子并行，不照搬无界树或整套协作协议 |

对照后发现原清单不足：只衡量并行耗时，没有把主上下文节省量单独验收；只有通用任务输入，缺少有界任务角色与模型选型；固定同步批处理可能失去主子同时工作的收益；子上下文的项目指令/Skill 来源与版本边界不够明确；“5 个实例×3 次”不足以直接支持稳定的 p95 结论。以下任务已补齐这些决策点。

## 4. 最小调用契约（拟实现）

```text
用户 → 主 Agent 的现有 execute 循环
       → subagent({ tasks: [...] })
         → Runtime 校验身份、范围、预算并记录调用
         → 至多 2 个只读子任务并行复用现有循环
         → 返回逐项状态、有界结论、证据引用和用量
       → 主 Agent 按需复核、修改、验证与交付
```

- 主 Agent 深度为 0，子 Agent 深度为 1；任何继续委派的请求在 Runtime 执行边界拒绝。只写提示词“不要再开子 Agent”不合格。
- 只暴露一个工具，建议输入为 `tasks[{taskId, objective, context, resourceScope, expectedOutput, role?}]`，允许单个任务和有界批次；`role` 首版只从宿主登记的少数只读任务类型中选，省略即通用只读，不接受任意系统提示。深度、父身份、权限、硬预算与真实路径边界由宿主生成；模型参数只能申请更小范围，不能授予权限。
- 首版建议每批最多 4 项、同时最多 2 个子任务；同一父 run 的累计子任务数也封顶，初值 4。配置取保守值，SA-09 根据实测调整。这些限制还必须受全局容量与父预算约束，不能靠连续多批绕过。
- 首版调用等待本批任务结束，主 Agent 不在等待期间另跑本地工作。收益来自子任务之间的并行与上下文分离；同步等待占比进入 SA-09 账本。如等待成为主要瓶颈，再由 SA-11 评估主子同时工作；不预设需要完整的 spawn/wait/send_message 协议。
- 外层 `subagent` 调用按 exclusive 处理，防止同批普通写入与子任务读取重叠；只读子任务的内部并行受本批预算约束。若外层资源判定需要审批，由统一规则判定，不能将整个委派工具粗暴标成 safe read 来豁免所有内部访问。
- 输出包含逐项 `taskId`、运行标识、终态、模型结论、证据引用、完整性、未解决项；使用量与执行状态来自 Runtime。明确区分完成、部分完成、失败、取消、超时、需用户输入、预算耗尽；具体枚举应映射现有契约，避免再造一套冲突状态机。
- 首版子工具白名单以可证明只读的内置能力为准；排除 exec、交互终端、任意插件/MCP 调用和外部 Agent 启动通道。命令名字看起来只读不构成证明。网络读取仍受现有 Web 全部硬边界约束。
- 子任务相互不可见全文转录；不复制整个父会话。只传目标、必要证据、资源范围、验收标准以及 Runtime/SOUL/语言约束。明确记录相关项目指令与 Skill 的来源及版本；只有宿主允许且与子工具权限兼容的内容才能进入子上下文。子任务独立上下文中的目录固定；父目录不随启停或忙闲切换而改变。

### SA-00｜冻结效率基线与委派条件（P0 / S）

依赖：无。入口：本任务书、`docs/reference/cache-95-acceptance.md`、现有 `scripts/audit-cache-usage.mjs` 与 `packages/harness/src/model-observability.ts`。

- [ ] 每类预先写明相同输入、产物质量检查、任务终点、允许成本与失败定义，先运行单 Agent 基线。基线与实验都保留完整调用账本。
- [ ] 写入主循环工具说明：仅在子目标边界明确、能独立完成且预期收益超过分派/汇总成本时委派；能直接回答、一次工具可完成或尚缺关键用户信息时直接处理。
- [ ] 对照“主 Agent 直接读取全部材料”与“子 Agent 返回有界结论”，冻结主上下文增量、主 Agent 后续压缩次数、子任务重复读取量和总模型用量；上下文隔离只能在完整账本下算收益。
- [ ] 明确用户直接要求使用/不使用子 Agent 时的路由：在权限与硬边界内遵循用户意图；任务不可独立或超预算时给出真实状态，不隐式忽略。
- [ ] 记录哪些参数为本方案建议，哪些是用户硬要求；不把“建议并发 2”变成永久产品限制。

验收：负载、指标与阈值在实验前冻结；没有新增规划模型请求；简单请求测试不启动子 Agent；“降低主上下文”与“降低总成本”分开报告。

- [ ] 子 Agent 使用固定受限工具目录；执行边界和委派入口均拒绝 depth >= 1 的新委派，身份缺失或矛盾时拒绝启动。

### SA-02｜复用循环并隔离执行上下文（P0 / L）

依赖：SA-01。入口：`packages/runner/src/runner.ts`、`runner-execute.ts`、`runner-finalize.ts`、`packages/harness/src/stages/execute/`。

- [ ] 通过薄适配入口复用现有 bounded loop；子运行拥有独立消息、局部预算视图、工具证据与文件观察身份，不新增 stage 或复制循环实现。
- [ ] 明确子运行不是普通用户会话：不新增侧栏会话、不递归获取父会话回合所有权、不向父对话发布子最终答案、不触发普通会话自动压缩/长期记忆写入。
- [ ] 注入有界上下文及 SOUL/语言；输出超长时由 Runtime 标记截断，必要时主 Agent 读取证据，不额外启动“总结 Agent”。
- [ ] 提供少数宿主登记的只读任务类型（例如代码定位、外部资料核对、独立审查），各有简短用途说明和返回格式。首次只用一份通用工具 schema，以参数选择类型，避免按类型增减会话内工具目录；未命中类型仍可做有界通用任务。
- [ ] 明确项目规则、运行时 SOUL、相关 Skill 和父任务证据的加载顺序、来源身份与上限；不能因子上下文独立而漏掉适用的硬约束，也不能把 Skill/外部文本提升为授权。
- [ ] 按读取路径维持 memory_tree 的索引导航与访问账本；子任务没有记忆写入权。网页与其它外部内容保留不可信属性。
- [ ] 父 Agent 的文件 observation 不因子结果返回而被登记为已读；主 Agent 写入前通过自己的 read 获取当前观察。

验收：两个子任务无历史串流；父会话只有主 Agent 的正式交付；子运行不新增自动压缩调用；缺失或不兼容的任务类型/Skill 有清楚回退；无父会话锁等待自身的死锁；普通聊天路径回归通过。

### SA-03｜权限、资源范围与审批归属（P0 / L）

依赖：SA-01、SA-02。入口：`packages/safety/src/permission-boundary.ts`、ToolExecutionService、`packages/app/src/main/` 与 Renderer 审批入口。

- [ ] 子可用范围取父已授权范围、委派资源范围、子工具白名单的交集。每次真实内部工具调用重新判断权限；外层 subagent 获批不等于所有未来动作获批。
- [ ] 保留完整数据根边界、容器外/unknown 访问、核心源码只读、危险命令硬拒绝及网络策略；未经批准不得提前扫描外部目录。
- [ ] 将审批明确关联到父任务和具体子任务；共用宿主审批入口，避免多个子实例各弹一次或共享一个 approvalGranted 放大授权。等待与取消遵循现有权限流程。
- [ ] 运行中权限收紧后不再派发超出新权限的调用；旧检查点恢复重新检查当前授权，历史批准不作为永久凭证。
- [ ] 子任务需要用户信息时先返回结构化待决事项，由主 Agent 合并提问；不允许多个子 Agent 直接抢占用户对话。真实权限审批仍保留其 Runtime 事实归属。

验收：三种权限模式 × 容器内/外/unknown 的拒绝和审批测试通过；一项批准不解锁兄弟调用；被拒子任务不让其它已完成结果丢失。

### SA-04｜共享预算、并发和超时（P0 / L）

依赖：SA-02、SA-03。入口：现有工具调度、模型调用预算入口、`packages/config/`、`packages/harness/src/context.ts`。

- [ ] 所有父子模型请求在发送前向同一 root 账本原子预留调用额度；重试、纠错、总结及恢复继续扣同一份预算。给父 Agent 留出最终综合/交付额度。
- [ ] 为子任务设置局部调用、输入/输出、时长与返回大小上限；局部额度从父可用额度中分配，不能每个子 run 重新领取完整 maxModelCallsPerRun。
- [ ] 复用现有并发机制并补齐共享容量约束：跨父 run 的子任务总量和 Provider 请求不能随实例数无界放大；预算/槽位不足明确排队、拒绝或降低并发。
- [ ] 原子记录真实用量；Provider usage 缺失时标记未知，不能当作零。估算 token 与实际计费分开；不能宣称仅凭估算实现精确费用硬限额。
- [ ] 默认子任务继承父 run 模型；可在宿主配置中为只读任务类型选已配置且允许的模型，记录最终实际模型、回退原因与费率版本。先用同模型建立质量基线，再比较较低成本模型；模型选择不能由子任务自行放宽。
- [ ] 外层工具超时与子截止时间统一，避免默认 60 秒到期后留下后台孤儿；扩展超时只针对受控委派调用，不无条件放宽全部工具。
- [ ] 等待父工具的任务不占尽所有模型请求槽位；子内部工具执行不能再次等待被父持有的同一独占锁。

验收：并发抢最后一个额度不会超发；父与子合计达到原总上限后不再请求；替换成低成本模型仍通过相同质量检查；多会话压力下容量有界；无重入死锁，额度和槽位在失败/取消后正确释放。

### SA-05｜停止、部分失败与恢复幂等（P0 / L）

依赖：SA-04。入口：`packages/tools/src/tool-execution-control.ts`、Runner durable 基础设施、已有检查点与执行日志。

- [ ] 父停止信号传递到排队子任务、在途模型请求、工具调用及审批等待；停止后禁止再派发，未确认终止的请求如实保留状态。
- [ ] 一个子任务失败不直接取消独立兄弟任务；父整体取消、父预算耗尽或权限整体撤销才停止受影响的全部任务。返回成功与失败混合结果。
- [ ] 以父 run + toolCallId + taskId 绑定子调用与结果；先持久化意图，再启动。外层工具超时、恢复重放不得重复启动同一子任务。
- [ ] 已完成结果复用；首版对崩溃时未完成子任务明确标记 interrupted/unknown，由主 Agent 在剩余预算内决定是否新开一次有记录的尝试，不默认无痕重启。
- [ ] 持久化父子预算与结果关联，旧版本无子任务字段仍可恢复；父结束后清理有界临时上下文和句柄，保留必要的脱敏审计。

验收：覆盖启动前、请求在途、结果已存但外层未返回、父交付前四个故障点；不重复计费性派发、不丢已完成证据、不留下继续运行的孤儿；不把 unknown 说成取消成功。

### SA-06｜可追溯结果与主 Agent 综合（P0 / M）

依赖：SA-02、SA-05。入口：`tool-result-persistence.ts`、Runner 执行日志、现有 Web citation 与 VERIFY 契约。

- [ ] 工具返回有界模型结论与 Runtime 证据引用；包含来源、文件路径/读取版本或本轮合法 citation、局部验证状态、遗漏/截断和未决问题。
- [ ] 子模型自述“已验证”不产生 pass；VERIFY 仍只依据 Runtime 可证明的事实。不自动相信互相冲突的结论，不做简单多数投票。
- [ ] 主 Agent 将子输出作为工具数据，不作为新系统指令；对冲突、关键修改依据和过期文件按需重读核实，避免把全部原始材料重新塞回主上下文。
- [ ] Web 来源引用在父 root 的本轮 Runtime 证据范围内校验并保留出处；不得伪造新 citation，也不得为恢复持久化整页正文。
- [ ] 子任务结论、主 Agent 综合与最终发布具有不同身份；正式交付继续走现有回复 settlement 注册表，重启和并发不会重复发布。

验收：伪造引用、冲突结论、截断证据、过期文件与提示注入场景不产生虚假成功；父交付能追溯到具体子调用和真实工具证据。

### SA-07｜对话内进度与问题可发现（P1 / M）

依赖：SA-05、SA-06。入口：`packages/app/src/renderer/chat/agent-tool-row.tsx`、共享活动投影、审批和恢复 UI。

- [ ] 复用工具活动行，默认显示任务名、已完成/总数与整体状态；展开才看逐项结果、用量与来源。不新增 Agent 组织图或单独侧栏会话。
- [ ] 父任务 Stop 覆盖所有子任务；切换会话、窗口重开后进度归属正确，终态不被过期事件覆盖。
- [ ] 失败、待批准、待输入、超时、部分结果和未知状态始终可发现，不能被“全部完成”折叠隐藏。
- [ ] 自然语言任务说明/结论来自真实模型并保留来源；按钮、进度、路径、权限和错误由 Runtime 提供。没有合法模型文案时只显示 Runtime 状态。

验收：真实 Electron 验证并发完成、一个失败、取消、审批、切换会话及重启；界面不卡住，用户能区分工具执行完成与任务质量已验证。

### SA-08｜父子完整成本账本（P0 / M）

依赖：SA-04、SA-06；可与 SA-07 独立推进。入口：`packages/harness/src/model-observability.ts`、`usage-state.ts`、Runner execution-log 和缓存验收脚本。

- [ ] 每个请求关联 rootRunId / childRunId / purpose / attempt；以请求唯一身份去重，父聚合引用子账本，避免重复计数。
- [ ] 合计所有输入、缓存输入、未缓存输入、输出、模型请求、失败/重试、排队、子执行、主综合与交付总耗时；记录峰值并发与内存。
- [ ] 保留现有 Provider/UI 口径，并补充父子完整任务成本投影；缓存比率按 sum(cached)/sum(input) 汇总，不平均各子命中率、不删除低命中调用。
- [ ] 区分用户审批等待与系统执行耗时，同时公布端到端总时间；不得通过剔除等待或汇总时间制造提速。
- [ ] 把外层同步等待、最慢子任务拖尾、父汇总重读、主上下文增量和子上下文增量分别列出；若主上下文减少但总输入增加，如实报告转移成本。

验收：模拟账本与真实 Provider 记录可对账；任一子调用失败或 usage 不可用时仍计入请求总数并显式标未知；缓存现行红线不被子会话拆分绕过。

### SA-09｜成对实测、启用条件与文档收口（P1 / L）

依赖：SA-00～SA-08。

- [ ] 同模型/配置/数据/产物标准，对每类至少 5 个冻结实例运行单 Agent 与同步子 Agent 两组，每实例至少 3 次交替运行；另将低成本子模型作为独立组，不与同模型实验混算。记录缓存冷热条件、网络与限流，不挑选最好的一次。
- [ ] 建议预设门槛：所有安全与深度约束用例通过；同一质量检查无退步且成功数不低于基线；适合委派的任务端到端中位数至少减少 20%，总费用增加不超过 10%；或总费用减少至少 20%，中位数不恶化超过 10%。首批样本只报告最大值、失败率和各次延迟；p95 守门须另行扩大样本，并在实验前确定样本量，不能用 15 次/类声称稳定 p95。
- [ ] 若真实价格/usage 不可获得，报告成本未验证，不判定成本门槛通过。各任务类别分别报告；明确列出没有收益或变慢的类别。
- [ ] 简单任务不派生子任务、不增加模型调用；费用/调用、质量或现行缓存红线未通过时，不扩大默认使用范围，缩减不适合的委派类别或保留实验开关。
- [ ] 若同步等待或最慢子任务拖尾抵消收益，记录为 SA-11 的输入；不因基础版未过延迟门槛就断言“所有子 Agent 方案无效”。若单任务也没有上下文或成本收益，则先收缩委派规则。
- [ ] 实现阶段按影响范围运行测试、类型检查、`pnpm.cmd check:repo`，完成真实 Provider、Electron 停止/恢复验收；新增源码与领域 README 同次提交。
- [ ] 更新项目状态与核心流程说明，准确写明只读阶段能力、单层硬边界、同步等待限制、实测收益和未完成项。

验收：提交逐次脱敏账本、成对报告、失败样本与 UI 验收证据；只有数据满足门槛才标记同步第一阶段完成。收益阈值是本方案建议，可在实验前调整并记录原因，不能看过结果后降低门槛。

### SA-11｜测量后评估主子同时工作（P1 / L，条件触发）

依赖：SA-09 留有逐次账本；同步等待或最慢子任务拖尾对端到端耗时有显著影响时启动。该项不要求 SA-09 的同步方案先通过收益门槛。

- [ ] 先从账本区分“主 Agent 在等待时确有独立可做工作”和“任务实际上依赖子结果”；只在前者上设计父子同时工作。若只是批次拖尾，可先试按完成顺序返回局部结果/提早结束无价值任务。
- [ ] 比较最小异步契约（启动返回任务 ID、订阅或查询进度、等待指定任务、停止指定任务）与当前单一工具的批次结果；只引入能解决已观察瓶颈的动作，不自动形成通用消息总线。
- [ ] 每个进行中的任务仍属于原父 run；父主循环恢复、预算耗尽、权限变化、最终交付或停止时，Runtime 明确处理未完成子任务，结果不能在父回复后无主地发布。主 Agent 最终回答若依赖子结论，必须先取回已完成证据并处理未完成状态。
- [ ] 主子并行读写同一工作区时，沿用 SA-03/SA-10 资源仲裁和 observation 规则；读到的旧版本与迟到的子结果标注过期，不能以完成顺序推定事实新旧。
- [ ] 用 SA-00 冻结任务重做单 Agent / 同步委派 / 异步委派三组对照，完整统计额外轮次、等待、取消、缓存与父汇总成本。

验收：只有质量不退步且同任务真实总耗时或总成本改善时才启用异步模式；父结束后无孤儿或迟到的正式回复。若没有可并行的主任务，保留同步工具即可，SA-11 记录“不引入”的测量结论。

### SA-10｜按收益开放子 Agent 写入（P2 / L，后续阶段）

依赖：SA-09 的同步方案或 SA-11 的异步方案通过收益验收，且只读委派后由主 Agent 落地已形成可测瓶颈。

- [ ] 先支持明确且互斥的文件范围；主/子对同一资源的读取和写入统一仲裁，同路径竞争排队或拒绝。跨子执行实例的调度不能只依赖批次内冲突检测。
- [ ] 保留 `read → observation(revision) → 写前 revision 校验 → checkpoint → mutate`；不共享“已经读过”的身份、不用 Git checkpoint 替代当前 revision。
- [ ] 父 Agent 使用产物前读取当前版本并复核结果；共享工作区、用户编辑和外部进程变化均可能使证据过期。声明独立文件并不能证明依赖关系独立。
- [ ] 再评估 exec/测试：无法证明范围的命令保持 exclusive，并正确挂起/失效相关观察；shell 能启动外部进程，无法硬限制其再启动 Agent 时不向子任务开放该能力。
- [ ] 子写入照常审批、登记副作用和恢复结算；unknown 不重放，取消不声称自动回滚。保护根、符号链接和范围不明访问继续执行原有硬拒绝。
- [ ] 重跑并发写、用户外部编辑、取消中途写入、权限撤销、崩溃后结算以及效率对照。

验收：无丢失更新、无观察越权、无重复副作用，新增写能力有实际效率收益；不满足时第一阶段继续可用，SA-10 保持未完成。

## 6. 实施顺序与交付边界

顺序：SA-00 → SA-01 → SA-02 → SA-03 → SA-04 → SA-05 → SA-06 → SA-07 / SA-08 → SA-09。随后依据账本分别决定 SA-11（异步）和 SA-10（写入），不把它们作为首版必经阶段。这里描述实施依赖，不要求在当前任务中启动开发子 Agent。

第一阶段完成必须同时满足：工具可用、Runtime 单层硬限制、父子权限和预算正确、停止/恢复可靠、证据与费用可追溯、真实任务效率门槛通过。只增加一个能调用模型的工具，不算完成。

本次交付仅为任务书与文档索引。源码审查不等于子 Agent 实现、真实 Provider 测试或 Electron 验收；不得将这些待办勾为完成。
