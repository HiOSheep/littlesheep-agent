## 2. 目标界面与设计边界

### 追加需求的源码依据（2026-09-27）

- **用量现状**：[单轮用量卡片](../../packages/app/src/renderer/chat/turn-usage-card.tsx)已展示输入／输出、缓存、推理与完整性；[run 聚合](../../packages/app/src/shared/run-usage.ts)已有快照身份去重与部分数据标识；[Provider 持久化投影校验](../../packages/harness/src/durable-provider-usage-codec.ts)与 [Token 账本类型](../../packages/types/src/token-ledger.ts)区分 Provider 实报、本地计数与不可展示的安全估算。跨日、跨 run 的热力图须复用这些口径，不从界面可见消息重复求和。
- **本地 DSH 参考**：已只读检查用户本地 `@local/dsh-token-heatmap` 1.0.0 的 `package.json`、`lib/index.js` 与 `lib/client.js`；安装历史快照也引用该包，但本轮未确认 DSH 当前是否加载它。插件采用 371 天日历格、0～4 档颜色、月份／星期标注、每日输入／输出／事件数提示、总量／活跃天数／单日峰值／会话数、主题变量与横向滚动。Host 读取携带 Provider usage 的 `assistant/message`，跳过 `shadowed`，按服务端本地提交日归档；缓存每日与每会话贡献，用 revision 跳过未变日志，每 30 秒调度扫描并先返回缓存。以上是源码事实，不是实机验证。
- **借鉴边界**：借鉴日历布局、详情与主题适配；不引入 DSH 插件运行时、不复制会话日志或密钥、不默认导入 DSH 历史用量。LS 的数据身份、失败尝试、分叉、恢复、缺失值和日期规则另按 O5 明确；不沿用“未报字段填零”“事件数等于请求数”或固定间隔全库扫描作为正确性与性能契约。本地绝对路径不写入公开仓库，实施时按包名定位参考。

### 通用设计原则

- **内容优先级：** 用户需要处理的异常／决策 → 最终结果与产物 → 当前进展 → 可展开的过程与诊断。正常状态轻量呈现，失败、权限拒绝、未验证和待决策始终可见。
- **玻璃分层：** 侧栏、输入区、浮动任务条和菜单承担玻璃材质；长正文、代码、表格及密集设置内容使用稳定的低干扰底色。同一视觉层尽量共用材质，避免多层模糊叠加。
- **圆润风格：** 保留现有连续圆角；面板、控件、胶囊各自使用已有角色令牌，不把所有元素做成胶囊。
- **设置布局：** 保留左导航、右内容与全局前进／后退。优先重构分类和内容组织，复用现有页面能力、草稿保护与 API。
- **文字边界：** 前端负责布局、标签和真实状态；Agent 自然语言仍由真实 LLM 生成。不得为了统一卡片而拼装固定“任务总结”，也不新增额外总结调用。
- **已解决的基础交互默认不创新（用户 2026-09-27 追加，硬约束）：** 凡是 Linear / Cursor / Claude / ChatGPT / VS Code 已经解决得很好的基础交互，一律**沿用既有约定**，不发明新形式。判断标准：先说出这些产品在该场景的**既有做法**（例如流式输出不移动正在阅读的位置、显式"回到最新"入口、复制有确认、失败可重试、Enter 发送 Shift+Enter 换行且尊重输入法组合、运行中停止键始终可达、Esc 关闭菜单、弹窗焦点陷阱、保存失败保留输入、设置可按字段搜索），再说明 LS 目前**偏离**在哪里。**偏离且更差的**才是 P0/P1；**只是长得不一样的**最多 P2，且默认不做。若某个"改进"无法说成用户可见的结果，不做。
- **实施范围：** 主要落在 Renderer。权限判定、记忆写入边界、运行状态与验证结论继续由 Runtime 提供。O5 允许补充最小的 Main／Local App API 只读统计投影与应用数据根内的可重建派生索引；只有证据缺字段时才补必要记录，不新增执行循环或通用分析平台。
- **外观偏好：** 字号、主题和配色属于应用级用户偏好，切换对话不丢失，重启恢复；不进入 Agent 提示词，不影响行为配置、权限或用量口径。复用现有偏好保存路径并在实施时确定唯一所有者。

### 外观与用量的最小交付范围

- **字体大小**：提供界面字号与聊天正文字号调整；代码／终端字号放在高级项，可跟随或独立调整。提供预设、范围内数值调整、当前值、实时样例和恢复默认；范围先用现有 14px 聊天基线验证，例如 12～22px，最终上下限由窄窗口与高 DPI 验收确定。调整字号须同步行高、控件自适应与编辑器／终端测量，不用全窗口缩放代替文字偏好。
- **主题模式**：深色、浅色、跟随系统；分别保存用户选择与当前解析出的明暗状态。保留现有用户的深色外观，新安装默认跟随系统；监听系统变化，手动选择后不再被系统覆盖；首帧应用偏好，避免先亮后暗或先暗后亮。
- **自定义颜色**：在明／暗基底之上提供强调色、背景与玻璃表面色调；选择器配合合法颜色值输入、预设和恢复默认。实时预览使用草稿，明确“应用／取消”，保存有效配置后重启恢复；自动推导配套文字与状态色，低对比组合提示并提供可读回退，不要求用户逐个维护几十个颜色变量；不开放任意 CSS／脚本注入。
- **Token 热力图**：设置中的独立“Token 用量”页，消息用量卡片增加次级“查看历史用量”入口。默认最近一年，支持年份及总量／输入／输出切换；月份、星期、图例、精确每日详情、区间总量、活跃天数与单日峰值构成首版。模型／供应商筛选只基于实际记录到的身份；项目维度、费用估算、外部导入不纳入首版。
- **统计定义**：以已持久化的 Provider 实报请求为基础；总量优先有效 `totalTokens`，缺失时仅在输入／输出完整时求和，来源可查。缓存读写与推理属于拆分或子集，不能再次加到总量；本地上下文占用、安全估算与 embedding 不混入对话 Token。重试中实际发生且有实报的独立尝试应计入，事件重放／分叉复制／恢复不得重复计入；失败、中断且缺 usage 的请求列入缺失覆盖信息。
- **日期与数据保留**：优先使用原始请求完成／usage 事件时间，按明确显示的统计时区分日；默认系统时区，存储原始时间，时区变化重新投影。历史只有 run 结束时间时标注降级，不能伪称请求级日期精度。归档不改变实际消耗；永久删除会话后保留不含内容的历史用量摘要，并在删除说明中明确；清空用量统计作为独立明确动作，记录截止范围，避免回填后自动重现。实施须验证重建、删除与保留规则一致。
- **完整性与性能**：无调用的零、未记录／部分记录、未完成回填、读取失败与旧缓存分别呈现，未来日期留空。历史回填有界、可取消、可续接；统计先展示已保存投影，再增量更新，页面和启动不等待全历史扫描；刷新失败保留旧结果并标明更新时间和失败。

本轮实施应以以下结果作为完成条件：

1. **信息层级：** 默认能找到最终回复、主要产物和未解决问题；过程可展开，证据限制不被隐藏。
2. **设置效率：** 常用配置两次选择以内可达；字段搜索能够直接定位；保存失败保留输入，保存与生效状态明确。
3. **视觉一致：** 保留半透明磨砂与连续圆角；同角色控件使用一致规则；长正文和密集设置保持可读。
4. **操作可靠：** 停止、输入法、权限确认、删除、草稿保护、会话隔离及返回导航全部通过代表流程回归。
5. **动效与性能：** 转场可以打断，减少动态效果时无残留等待；记录同机同场景前后数据，不以主观感受宣称提速。
6. **证据完整：** 区分组件检查、真实 Electron 操作和安装包验证；只将实际通过验收的任务标为完成。
7. **自定义外观：** 界面／聊天字号、深色／浅色／跟随系统、自定义强调与表面色均可预览、保存、恢复默认；跨聊天、设置、弹层、编辑器、终端与重启保持一致，放大文字后关键操作仍可达。
8. **Token 热力图：** 跨日汇总与真实 Provider 记录对账一致；恢复、分叉、重放不重复；缺失不当零；按日详情、年度视图、图例、时区与覆盖范围可理解；零、未来、缺失、回填和失败区分；大历史回填不阻塞首帧和输入，换主题后可读。

推荐先交付“**异常与结果层级 + 设置导航重排 + 共享视觉规则**”，随后推进字段搜索、表单一致性和跨工作区流程，最后进行动效细化。这样每批都有可见收益，也便于定位和回退局部问题。

## 2026-10-02 文本输入焦点框移除（用户反馈）

用户报告"还有很多这种额外的框，显得很生硬，需要移除"，并给出一张输入区截图。同一路径在真实 Electron 窗口里按原样复现：双击对话标题条进入重命名后，字段自身的应用级 `:focus-visible` 轮廓把输入区框成一个方角矩形（实测字段 140×16 CSS px、`outline: 2px solid rgba(132,183,255,0.6)`、`outline-offset: 2px`，所在胶囊 24px 高，dpr 1.5），白色标题文字衬 `--selection-background` 底；胶囊、球体与选区的几何和像素都与截图一致。

### 判定与实现

- 文本框不再套用应用级 `:focus-visible` 轮廓。Chromium 对文本输入框在**任何**获得焦点的方式下（含单击）都匹配该伪类，所以这条规则实际等于"点进任何字段就多出一个方框"，而不是键盘专用提示；同一形状还出现在设置搜索框、设置模块搜索框、记忆编辑器、两个字号滑块和供应商密钥框等。
- 焦点改由承载字段的表面表达：字段自己的圆角表面在 `:focus` 时抬升填充或边框，圆角外壳内的无边框字段由外壳 `:focus-within` 抬升填充；滑块不再框住轨道，改成手柄上的柔和圆环（手柄伪元素必须同时给 `border-radius`，否则引擎会把方形盒子当作光晕画出来——本轮实测到）。
- 触及：运行任务条重命名（胶囊填充）、设置搜索与设置模块搜索（胶囊填充）、供应商密钥／供应商输入／模型行／设置行内字段（填充）、外观颜色值输入（填充 + 边框）、字号滑块（手柄圆环）、项目名输入（填充）。凡是不再画轮廓的地方同时显式 `outline: 0`，否则浏览器会退回 UA 默认焦点环，本轮实测到并一并修掉。
