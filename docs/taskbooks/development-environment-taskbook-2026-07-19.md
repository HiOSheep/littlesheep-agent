# LS 开发环境管理任务书 2026-07-19

状态：阶段 1-5 已完成基础管理闭环；正式运行时下载、签名校验和安装包分发仍待后续阶段。

最后更新：2026-07-19 10:13:03

## 目标

让 LS 在设置中提供独立的“开发环境”页面，统一管理 LS 自己使用的运行时和工具链版本。用户可以查看实际检测结果、填写目标版本、导入已经下载并解压的工具链、移除 LS 已管理版本，并在不修改系统环境变量的情况下让终端优先使用目标工具链。

这项能力服务于两个产品目标：

- LS 执行开发任务时不依赖用户手工配置外部 PATH。
- 用户仍能明确知道当前实际使用的版本，并保留版本选择、导入和移除的控制权。

## 设计边界

- 工具链统一存放在 `<data-root>/toolchains/`；偏好存放在 `toolchains/preferences.json`。`<data-root>` 是可迁移的 LS 应用数据根，不等同于 `workplace/`。
- 当前随 Electron 应用可直接提供的是内置 Node shim。Python、Java/JDK、Go、Rust、C/C++、.NET、Ruby、PHP、Git 和 PowerShell 已有统一登记、检测、导入和终端 PATH 管理入口，但尚未宣称随安装包携带完整二进制。
- 保存目标版本只保存偏好，不会伪造“已安装”。目标版本没有准备好时，设置页显示“目标待准备”；终端只使用已验证的 LS 版本，系统版本只能作为明确的降级来源。
- 版本可以填写精确版本或系列版本。例如 `3.12` 会选择已导入的最高匹配 `3.12.x`；导入时以可执行文件真实报告的具体版本作为目录名，避免多个补丁版本互相覆盖。
- Renderer 只能通过 Local App API 操作，不能直接读写工具链目录。导入由 Main 打开目录选择器，复制到 staging 后校验，再原子重命名并写入偏好。
- 系统 `PATH` 不会被 LS 全局修改。每个终端进程拿到一份派生环境，LS 管理路径排在系统路径前面。

## 已完成阶段

### 阶段 1：契约与登记

- 新增开发环境 ID、状态、来源、实际版本、目标版本、已导入版本和终端路径契约。
- 统一登记运行时、编译工具链和开发工具，设置页按类别展示。
- 版本标签严格限制为安全目录名，拒绝路径穿越和控制字符。

### 阶段 2：Main 管理器

- `DevelopmentEnvironmentManager` 负责偏好持久化、并发写入串行化、检测缓存、版本选择和终端环境派生。
- Electron 内置 Node 通过 LS shim 暴露给终端，不依赖系统 Node。
- 目标版本缺失时不静默切换到其他不匹配的 LS 版本。
- 版本检测失败或实际版本不匹配时，不把无效工具链路径注入终端。

### 阶段 3：安全导入与移除

- 只接受用户选择的已解压目录，源目录不会被移动或修改。
- 导入前后检查普通目录和符号链接，复制到 `<data-root>/toolchains/.staging/` 后完成可执行文件和版本复核。
- 复制成功后才原子进入版本目录；偏好写入失败会删除本次新目录。
- 移除只允许操作工具链根目录的直接子版本目录，并在没有剩余匹配版本时清理失效目标偏好。

### 阶段 4：Local App API 与设置页

- 设置导航和设置首页均可进入“开发环境”。
- 已提供状态查询、重新检测、保存偏好、导入和移除接口。
- 页面显示来源、状态、实际版本、目标版本、目录版本、可执行文件路径和已导入版本。
- 重新检测、取消目录选择、保存、导入和移除都有独立的忙碌/错误/成功状态，不阻塞其他设置页。

### 阶段 5：终端接入与回归

- 持续终端、一次性命令和流式命令均从同一管理器取得派生环境。
- 终端优先解析 LS 管理版本；未准备好时保留系统降级路径，但不更改宿主进程的 `PATH`。
- 已覆盖 Electron Node shim、偏好持久化、并发写入、路径校验、系列版本选择、移除和 Local App API 回归。

## 验收标准

- 设置页在正常启动、重启和数据根迁移后都能读取同一份版本偏好。
- 用户填写精确版本或系列版本后，页面明确区分“目标版本”和“实际生效版本”。
- 导入目录不被修改；导入中断、校验失败、偏好写入失败都不会留下半成品活动版本。
- 终端只接收已验证的 LS 工具链路径，系统降级状态可解释，宿主 `PATH` 保持不变。
- 移除版本不会删除工具链根目录外的路径，也不会留下指向不存在版本的偏好。
- 运行时下载加入前，必须先通过来源、哈希/签名、取消、恢复、清理和低磁盘空间验收。

## 后续维护规则

- 新增环境时同时修改定义、共享契约、检测候选、设置分组、终端 PATH 测试、文档和版本恢复测试。
- 任何版本选择逻辑必须先说明精确版本、系列版本和候选排序，不允许隐式使用“看起来最新”的系统版本。
- 不在 Renderer 中调用 `fs`，不把工具链复制进源码仓库，也不把用户下载包提交到 Git。
- 变更导入或移除事务后，至少运行开发环境定向测试、App typecheck、App build 和 `check:repo`；阶段完成再运行全量质量门。
