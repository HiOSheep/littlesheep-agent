# RCD S3A — 真实任务评测协议

## 目的与范围

本协议固定 LittleSheep 的任务评测输入、环境、独立验收、证据层级、指标和失败分类。运行器状态、`AgentResult.status`、`run_completed`、工具退出码和模型最终回复都是执行事实，不构成任务成功的替代 Oracle。

S3A 固定产品源码基线为提交 `d5015136ca9cf9583423361263b5bacba257a385`。任何产品源码差异都会使对应任务记录失去该冻结版本资格。评测脚本、Oracle 或测试夹具本身有变化时，产品提交仍须单独记录，同时保存评测器 Git/tree 指纹与任务定义哈希；带评测器覆盖层的结果不得伪称来自未变化的原验收工作树。

## 三个证据层级

| 层级 | 内容 | 可支持的结论 |
|---|---|---|
| A — Runtime 确定性测试 | 固定受控 Provider 响应、Runner/Harness/Tools、合成工作区和独立 Oracle | 工具链、安全边界、恢复、结算和确定性任务控制行为；不代表真实模型能力 |
| B — 真实模型任务 | 指定的 Provider、模型版本、参数、权限和预算，使用同一冻结任务与外部 Oracle | 该模型配置下测得的任务完成率和真实物理用量；需另外授权，S3A 不发起付费请求 |
| C — Agent 产品对照 | 在记录任务、环境、权限、工具与模型差异后对照 Agent | 对照任务上的交付与用户干预；同模型/同工具 Harness 对照与产品原生对照分别报告 |

层级不得互相汇总为一个“成功率”。本批仅运行 A；B 的运行协议已定义、实际任务结果保持 `not_run`，C 不启动。

## 运行流程

每项任务从冻结定义创建独立临时数据根和工作区，写入固定种子文件，确认授权和网络边界，然后通过标记的 Runner/Harness 执行适配器运行。Oracle 在运行后独立读取临时工作区、效果/调用记录或明确的本地服务日志；它不读取模型自述作为成功依据。报告先保存执行记录和 Oracle 结果，再执行 Runner 关闭、服务关闭及临时目录清理。清理失败属于评测基础设施失败，必须列出残留项。

任务使用受控 Provider 时，Provider 只按确定性脚本返回响应，不读取 Oracle，也不直接写入目标产物。工具调用仍经过 Runtime 工具链。只有适配器声明的层级可用于解释其结果。真实任务的任务定义可以暂时没有适配器，此时保持 `not_run`。

## 输入、复现与冻结

机器定义包含原始用户输入、初始文件内容、工具与权限范围、允许的网络目标、独立成功条件、失败/部分完成判定及清理规则。运行记录同时保存：产品 Git 完整 SHA、HEAD 状态、工作树 tree/diff 指纹、pnpm lockfile SHA-256、任务与场景定义哈希、适配器/配置哈希、OS/架构、Node/pnpm/Electron 版本，以及受控 Provider 名称。

产品源码在运行前后均须与冻结 SHA 的 tracked 内容一致。需要新增 S3A 测试/脚本时，它们作为明确的评测器覆盖层计算单独指纹；该事实与产品提交分开保存。不得把之前 dirty 验收中的结果改写为 clean-commit 结果。

运行示例：

```powershell
node scripts/s3a-eval.mjs --audit
node scripts/s3a-eval.mjs --run
node scripts/s3a-eval.mjs --task=CODE-01
node scripts/s3a-eval.mjs --suite
```

`--task` 运行一个受控适配器；`--run` 运行本批具有适配器的任务；`--audit` 只生成 24 项 RCD 场景审计；`--suite` 校验并输出 12 项任务集，不会声称执行任务。所有实际运行都写独立机器账本。默认账本位置与本次实现记录见 `rcd-s3a-baseline-2026-10-17.json`；系统临时目录中的工作区在退出时删除。

## 指标口径

- **任务成果：** 独立 Oracle 判定 `passed`、`failed`、`partially_completed`、`correctly_blocked` 或 `unverified`；另记录要求数、通过数、未验证数、产物和虚假成功声明。Oracle 判定与 Runtime 执行状态分列。
- **执行效率：** 从实际模型请求事件计数物理 Provider 请求；从 ToolInvocation/工具执行结果计数提议与真实执行；记录端到端用时、首次有效副作用时间、压缩/续接事件和未完成任务资源。受控 Provider 请求次数不等于真实模型请求消耗。
- **用量/成本：** 只接纳 Provider 物理回执中的 input/output/cache token 和可核验费用。字段没有可靠来源时 `unavailable`，不得由消息长度估算。
- **用户干预：** 从审批事件、恢复/继续输入事件与取消事件计数。没有事件来源的字段为 `unavailable`，不能把模型响应轮数算作用户干预。
- **安全与可靠性：** 记录真实工具/副作用次数、重复副作用、unknown effect/provider、权限拒绝、禁网外部请求、checkpoint/恢复异常和可信结构化结果与模型完成声明冲突。

## 状态与失败归类

评测基础设施状态与产品结果必须正交：`executed`、`blocked`、`harness_error`、`not_run` 是运行状态；产品结果由 Oracle 独立给出。有效的产品失败仍为 `executed + failed`，不得将其算作 Harness 故障。正确的安全阻断可为 `executed + correctly_blocked`，但不计作用户目标完成。

主要/次要失败原因使用以下集合：模型理解或推理、工具能力缺失、工具参数错误或执行失败、权限与安全阻断、网络和外部环境、预算耗尽或无进展、Context/Memory、恢复与结算、产物错误或缺失、验证证据不足、评测基础设施故障。主因说明因果上最早的任务失败点；次因记录促成因素。Oracle 必须引用证据。

## 安全与限制

所有工作区与数据根位于临时目录；输入和秘密均为合成数据。网络默认关闭；需要检索的夹具只使用显式 loopback 服务或内存 Provider。明确禁网场景不发请求。宿主 Shell 不视为 OS 沙箱。Permission V2、预算、Approval 和副作用语义沿用产品设置，不为提高通过率扩大权限。

S3A 不调用真实付费 Provider，不使用真实私人文件/Memory/密钥/外部账号，也不做竞品自动化。受控 Provider 结果只衡量执行机制。首批 12 项任务中尚未运行的任务保持 `not_run`；本批 4 个适配器的结果也不等于真实模型任务完成率。
