# UI 交互规范

LittleSheep 的桌面界面应当安静、有序、连贯，并保持统一的设计语言。

状态：规范性专项文档。当前实现状态和验证结果以 [项目状态](project-status.md) 为准。

最后更新：2026-07-13

## 产品原则

- 日常使用应当轻松、少打断，同时用户始终拥有对 Agent 行为的高度控制权。
- UI 的信息层级应服务于“用户产生想法，LS 负责落地”：减少用户寻找状态、搬运结果和重复操作的负担，不用装饰性信息抢占主工作区。
- 默认保持自动化安静运行。只有当前任务需要、决策被阻塞或风险要求明确同意时，才展示内部机制。
- 全局采用渐进式披露：默认呈现当前任务最有用的结果和最小状态，任务书、执行证据、记忆来源、阈值、权限、日志和高级设置按需展开。
- 渐进式披露不能隐藏失败、风险、权限拒绝、部分完成或待用户决定事项；这些信息必须出现在默认可见层。
- 任何改变持久状态的自动行为都必须可追溯；可恢复行为应在对应管理界面提供恢复或撤销入口。
- 高级自定义必须是可选的。默认设置应在用户不了解状态机的情况下，也能提供完整、稳定的体验。
- 少打断的设计绝不覆盖安全和授权要求。破坏性、不可逆或超出范围的操作仍需明确批准。
- 权限弹窗默认授予单次操作，并说明发起来源、操作风险和作用域。“允许本次对话”只能覆盖同一对话、同一来源（`agent` 或手动工作区）和同类操作，授权只保存在内存中，应用重启后失效，不能形成永久项目信任。权限弹窗应使用统一的进入/退出过渡，而不是决策后立即消失。

## 动效

- 新功能模块必须复用 renderer 的共享动效 token、presence 与 overlay 原语。当前主要实现在 `packages/app/src/renderer/styles.css` 和 `FadePresence`；后续按 feature 拆分可以移动文件，但不能复制出不同的时长、缓动和生命周期语义。
- 普通模块级进入和退出使用 `FadePresence` 与 `presence-layer` 语义。设置等根级工作区使用专用双向遮罩转场，不得再叠加普通页面首次淡入。
- 内部视图切换、空状态、状态行、列表和新挂载面板使用 `content-fade`。
- 展开/折叠表面使用 `disclosure-panel` 模式，不允许瞬间挂载或卸载。
- 可见页面、面板、浮层或路由不得生硬切换；每个可见转场至少要有淡入淡出、滑动、展开披露或缓冲加载状态。
- 所有两层阈值的尺寸交互都必须在正反两个方向使用共享的 `--two-stage-resize-motion` 时长和缓动。越过第二层阈值、反向越过阈值和松手收束，都应是同一段转场的正向或反向播放，不能分别做成瞬间状态替换。
- 动画保持克制：短暂淡入淡出、轻微垂直位移，不使用弹跳或夸张效果。
- 遵守 `prefers-reduced-motion`。

## 视觉风格

- 保持黑灰色视觉语言：表面克制、边框安静、控件紧凑。
- 相邻结构表面使用相同或非常接近的深灰色。避免刺眼的黑色条带、顶部与主体之间的硬边界；只有功能确实需要时才显示分隔线。
- 结构分隔线应是清晰的 1px 线。可调整大小的分隔条可以有不可见的命中区域，但可见提示只能是细线，不能做成宽槽、厚胶囊或粗重横条。
- 交互控件默认保持安静：空闲时不显示边框或填充框，悬浮/聚焦时显示略浅的表面和细微边框，内部间距保持紧凑。
- 禁用或不可用控件使用普通光标和弱化视觉，不使用警示或禁止光标。
- 紧凑文字控件应根据可见内容自适应宽度，不使用过长的固定胶囊。文字在悬浮框中视觉居中，箭头/图标要靠近其描述文字。
- 固定形状中的小状态图标应使用居中的几何 CSS/SVG 标记，而不是依赖字体字形，尤其是关闭图标、圆点和叹号。
- 避免紧凑控件周围过大的不可见悬浮区域；光标不在可见文字/图标组上时，不显示悬浮框。只有拓展工作区恢复带等明确承担边缘发现性的专用感应区可以例外，并且不得阻塞底层控件。
- 除成功、警告、危险等明确状态外，避免使用零散的高亮颜色。
- 新控件优先复用已有的按钮、胶囊、对话框、面板和列表模式，不要随意引入新形状。
- 新选择器优先复用模型、模式和推理程度控件已经使用的分组选择器/选项选择器语言。
- 文字必须适配容器，使用省略或换行解决溢出；不允许重叠或布局跳动。
- 空状态和右侧工作区内容应相对于可用工作区居中，排除侧边栏、标题栏和固定输入栏；不要用只在某一种窗口尺寸下看起来居中的固定偏移。

## 交互

- 对话框、浮层、子菜单、下拉菜单、临时侧面板和其他临时 UI 层，在可行时都应支持点击外部区域和按 Escape 自动收回。新临时层必须复用统一的外部点击收回模式，不要由每个组件自行发明一套。
- 当一个临时层已经打开，用户点击另一个临时层触发器时，应在同一次点击中直接关闭旧层并打开新层。不能要求用户先点一次关闭，再点第二次打开。
- 临时层切换也必须有动画。如果外壳位置不变，替换内容时使用交叉淡化或轻微滑动；如果是两个独立浮层，则让旧浮层按统一临时动效退出，新浮层进入，不能瞬间切换。
- 居中对话框和向导式创建流程应比紧凑浮层使用更慢、更易读的动效。应用可见状态前要确保初始隐藏状态已经绘制，避免打开时像瞬间挂载。
- 打开和关闭都必须平滑；预期有关闭动画时不能立即卸载。
- 用户自然需要更多空间的主要工作区应可调整大小。调整手柄要低调、可键盘操作、限制在可用范围内，并将用户偏好的尺寸持久化。
- 可调整分隔条必须跟手。拖动期间直接更新布局变量并禁用布局过渡，只在松手时持久化 React 状态/本地偏好。将侧边栏分隔条拖到最左侧应折叠侧边栏，展开宽度仍需限制在最大值内。
- 可折叠侧边栏不能显示损坏的狭窄中间状态。使用两层阈值：第一层将展开状态限制在可读最小宽度，第二层触发平滑折叠。两层之间只有光标继续移动，应用布局和侧边栏视觉保持不变。除非设计另有明确比例，折叠阈值应为可读最小宽度的一半。
- 拓展工作区分隔条正反两个方向都遵守同一两层阈值规则。向右拖动时在 280px 停止缩小，继续到 140px 之前处于只有光标移动的缓冲区，越过后平滑折叠出布局；向左拖动时在对话区自适应可读宽度停止压缩，剩余宽度达到一半前只移动光标，越过后平滑折叠对话区并让拓展工作区占满核心区。反向越过第二层阈值时必须反向播放同一动画，松手停在缓冲区时回到对应第一层阈值。
- 拓展工作区完全折叠后不得占用核心工作区宽度，也不能留下固定分隔线或图标。将右侧全高窄条作为不阻塞点击的感应区域：光标悬浮在该区域任意位置时，在垂直方向中部显示一个紧凑的重新打开图标，底层对话和输入栏仍可点击。空闲时窄条完全不可见。延迟显示的提示文字固定在图标左侧并保持稳定间距，同时为用户消息预留足够右边距，避免图标与消息接触或重叠。
- 输入栏应保持紧凑。主行只放最常用控件，文件/工作区操作和详细运行时设置等次要选择放进平滑的子菜单。
- 空对话状态保持无框且安静。不要把欢迎语放进装饰卡片；相对于可用对话区居中文案，让输入栏保持主要可操作表面。
- 输入栏高度应随输入内容自动变化。不要提供手动调整输入栏大小的手柄，也不要在输入栏上方放固定分隔线；文字超过实用高度时在 textarea 内滚动，而不是用可见调整线割裂对话和输入栏。
- 输入栏控制行在结构上分为左右两侧：左侧控件左对齐，右侧运行时/发送控件右对齐，文字和图标的中心线保持在同一水平线上。
- 文件上传和工作区选择放在输入栏的添加菜单后。已选择的自定义工作区显示为可移除的紧凑标签；默认 Agent workplace 不显示标签，保持输入栏简洁。
- 输入栏上下文占用保持紧凑。空闲状态只在运行时/模型选择器旁显示小圆环，不为圆环添加悬浮框或额外效果。详细上下文窗口占用显示在悬浮/聚焦浮层中，不能占布局空间或推动输入栏控件。上下文总长度必须按模型区分，并依据供应商文档更新，不能写成全局固定值。
- 上下文占用必须区分两个真实来源：请求前的本地 `ContextSnapshot` 记录客户端实际装配和预算的内容；请求后的 Provider usage 记录供应商实际处理/计费口径。二者在详情中分别标明“当前装配”和“上次请求”、模型及时间点，不能混成一个无来源数字。
- 只有本地计数使用与具体 provider/model 匹配的 tokenizer，并覆盖最终序列化载荷时，圆环才能表示当前装配占用；否则不得用字符换算或“约”数冒充真实 token。此时可以显示上次请求的 Provider usage，但必须明确它是历史请求结果，不代表尚未发送内容的实时占用。两种来源都不存在时圆环保持无进度状态。
- 圆环进度使用对应真实已用量除以所选模型上下文窗口。详情浮层使用紧凑的 `k`/`M` 单位，不显示 `token` 这个单词，并能查看 System Prompt、最近对话、记忆、工具结果、附件和工作流状态等来源分类；Provider usage 与本地 ledger 差异超过阈值时显示诊断入口，不用任一数字静默覆盖另一数字。
- 运行时选择器使用主面板加轻量子菜单。推理选项直接显示在主面板；模型和供应商选择从主面板对应行打开子菜单，并用分隔符保留视觉分组。
- 尚未实现的功能不能提前占用可见输入栏控件位置。
- 侧边栏应将创建对话和对话历史归入同一个“对话”大类。
- 从主侧边栏创建项目时，先打开居中的 LittleSheep 自有对话框/菜单，不能立即打开系统文件夹选择器。菜单应支持选择已有目标文件夹或创建新文件夹。项目创建/选择完成后切换到该项目工作区，从新的项目对话开始，并自然展开“对话”分组。
- 对话归属必须明确，并与工作目录独立。独立对话只出现在“对话”下；项目对话只出现在所属项目的第三级下。独立对话选择了某个文件夹时，不能因路径相同被复制到项目下；项目的归档/删除/恢复也不能因路径巧合影响独立对话。
- 项目移动或重命名后，从该项目的子菜单选择“重新定位项目”，不得通过重新添加文件夹生成另一份项目身份。重绑定保持原项目 ID 和侧边栏位置，并同步项目会话、记忆、投影、工作区标签、草稿和导航状态；目标路径已属于其他活动或归档项目时必须明确拒绝。
- 主侧边栏的“项目”类别沿用“对话”的视觉语法，但使用三级结构：根“项目”类别、具体项目行、项目下的对话行。根类别是结构节点，不可删除；项目行和项目对话行可以归档或删除。从项目行打开的对话，默认工作区必须是项目文件夹。项目打开或激活时保持稳定的默认顺序；用户排序放进项目菜单。
- 对话行可以按真实对话活动时间排序，但单纯打开或浏览对话不能更新顺序。真实消息更新导致顺序改变时，行移动应使用轻微过渡，而不是瞬间跳动。
- 整个侧边栏可通过位于全局前进/后退按钮左侧的紧凑标题栏控件折叠。折叠/展开应同时动画化侧边栏宽度、调整手柄可见性、标题栏表面边界和控件图标状态，不能瞬间替换图标或吸附布局。
- 侧边栏分组箭头只表示展开/折叠状态。分组级创建和更多选项应在分组标题悬浮/聚焦时显示为紧凑的右对齐控件。
- 侧边栏子行的尾部操作要与父级分组标题使用同一个右侧操作列。删除或归档操作默认隐藏，仅在行悬浮/聚焦时显示。通过缩进、对齐和展开状态表达层级，不用解释性文字填充界面。
- 归档是清理侧边栏，不是删除。归档项目和对话应从主侧边栏消失，并可在“设置 > 归档”中恢复。归档管理器应复用侧边栏层级：项目归档包含其归档的项目对话，独立归档对话放在单独的“对话”分组。恢复属于已归档项目的对话时，必须同时恢复项目记录。归档中的永久删除可以删除 LS 记录和会话文件，但绝不能删除用户真实项目文件夹。
- 设置是固定在侧边栏左下角的根级入口，是特殊的高权重入口：默认只显示齿轮图标，悬浮/聚焦齿轮时才显示“设置”文字；API key、外部渠道、记忆、技能和未来模块的权威管理页都属于全屏设置工作区，其中高频页面可以按下一条规则在主工作区复用同一个内容组件。
- 主侧边栏中的记忆树、插件和已安排等高频入口应直接在核心内容区打开对应的完整内容页，不触发左下角设置入口的圆形转场，也不切换成设置侧边栏。设置工作区内仍复用同一个内容组件；主侧边栏与设置侧边栏的选中状态、展开状态和导航入口彼此独立。除本地搜索这类纯临时功能外，不要把这些入口实现成一次性小浮窗。
- 主侧边栏的本地搜索属于与核心内容路由独立的临时层。在对话、记忆树、插件、已安排等任意主工作区页面都必须能直接打开；打开搜索不能退出或替换当前页面，关闭后仍停留在原页面。选择搜索结果时才切回对话页并打开对应会话。
- 设置入口属于侧边栏系统，必须随侧边栏一起折叠、展开、移动、隐藏和显示，不能作为独立固定控件漂浮。设置打开后，同一个入口出现在设置侧边栏中，再次点击可关闭设置。
- 设置使用与主工作区相同的交互模型：左侧是设置大类侧边栏，右侧是选中的子模块内容区。不要做成居中的卡片列表或类似模态框的独立表面。
- 设置侧边栏按领域分组，例如通用、工作、记忆、拓展和连接。新增设置页优先加入最接近的已有分组，只有确实没有归属时才新增类别。
- 记忆树管理是 LS 的核心模块，应拥有独立的设置页面/组件。它要与 Skills 分开：记忆树负责长期记忆、项目分支、daily 记忆、经验召回和深搜可见性；Skills 负责可复用能力文档和工具指令。
- 记忆树资源目录遵循渐进式披露：列表默认只显示层级、名称、类型、状态和权威来源，展开后才显示路径、索引键、生命周期审计和管理动作。停用可恢复，移除登记不得删除来源文件；T0 核心资源停用必须确认。run-scoped 资源和项目记忆投影继续由各自生命周期控制面管理，不展示会产生错误所有权暗示的通用按钮。
- 设置工作区从左下角设置入口以偏心圆展开，再回到同一原点折叠。打开和关闭必须是同一个转场原语的反向播放，不能写两套实现。正反方向使用同一原点、时长、缓动、转场状态和边缘元素。转场必须双向遮盖：进入工作区时从同一原点揭示，离开时从同一原点覆盖/揭示离开的页面，让两页连续连接而不是一页突然出现在另一页后面。移动的遮罩边缘应有清晰线条和轻微光晕，正反方向都能看清边界；边缘必须在转场层绘制，不能放进被裁剪的页面表面。页面遮罩与边缘使用同一个动画半径驱动，被揭示的工作区始终完全不透明，避免边缘尚未到达时透出后方文字。
- 性能方面，当前已验证的设置转场使用原生 `clip-path: circle()` 与光晕边缘 `transform: scale()`，正反方向共享 750ms 时长。不要在没有性能剖析和视觉回归的情况下改回曾导致当前应用主线程卡顿的 `<length>` 自定义属性插值方案；任何替代实现都必须验证帧稳定性、遮罩/边缘同步和动画可打断性。
- 从入口控件开始的根级转场必须桥接该入口。如果进出工作区有相似入口，就用转场层桥接覆盖交接，避免页面揭示过程中控件闪烁、跳动或瞬间切换视觉状态。如果入口有悬浮展开文字，只要光标仍在其上，就要保持展开状态。导航入口的转场桥接在打开/关闭期间应保持可点击，允许用户打断并反向播放动画。
- 设置等根级工作区打开时，被覆盖的工作区必须同时视觉隐藏且不可交互。键盘焦点、辅助功能导航和指针事件都不能穿透转场层到达后方控件。
- 设置打开/关闭揭示期间，设置内容应提前渲染，只因为圆形遮罩移动而显现。不要在设置页内部额外加入首次打开淡入或文字刷新；设置子页之间的导航才使用内部页面淡入。
- 关闭根级工作区时，要保留关闭开始时正在显示的子页，直到退出动画完全卸载。再次从根入口打开时可以有意回到默认根页，但关闭动画必须从用户当前所在子页返回，不能先跳到默认页再关闭。
- 设置等全屏工作区必须复用全局标题栏/导航组：侧边栏折叠、前进、后退、LS 图标和 LittleSheep 标题。不要为这些页面再创建一套局部前进/后退标题栏。
- 前进和后退是全局应用历史控件，不是页面局部控件。历史项应保存页面路由及有界的页面状态快照，包括拓展工作区展开/折叠/全屏、活动标签、打开标签、文件导航器折叠状态和目录展开路径。历史只保存在内存中，必须限制最大条目和集合长度，不能复制消息正文、文件内容或目录响应；应用重启后历史清空。
- 左侧边栏与核心工作区相互独立。核心工作区包含同级的主对话和拓展工作区；打开、调整大小、全屏或折叠拓展工作区可以改变/覆盖主对话，但不能改变侧边栏布局或可见性。
- 持久化用户偏好的拓展工作区宽度，但根据当前窗口和侧边栏尺寸计算实际分栏宽度及对话区自适应阈值。分栏模式要保持两侧可读，不能盲目恢复过大的旧宽度。只有越过拖动交互的第二层阈值或使用明确的全屏控件，才进入拓展工作区全屏；全屏只覆盖核心工作区，侧边栏保持独立。
- 拓展工作区全屏、退出全屏、折叠和重新展开都属于普通全局历史状态。返回/前进应恢复对应快照并沿用共享转场，不能再写独立于历史栈的特殊返回分支。
- 拓展工作区使用真实标签栏。标签可从 `+` 菜单新增、点击切换、独立关闭。关闭当前标签时选择最近的剩余标签；关闭最后一个标签时折叠拓展工作区。活动标签和打开标签集合都要持久化。
- 拓展工作区可以有自己的文件导航器，但它必须在视觉和概念上与标签栏分离。标签代表打开的工作面，例如审查、产物、终端、浏览器、侧边对话或具体文件；文件导航器不能占用顶层标签。文件导航器是右侧项目/文件定位器，可折叠为窄图标栏，应覆盖当前工作面而不是改变拓展工作区尺寸，也不能替代或混用标签模型。
- 从文件导航器打开文件时，必须创建或激活顶层文件标签。文件预览、编辑、保存和外部打开动作属于该文件标签；导航器只负责定位文件。
- 文件标签仍应保留同一个右侧文件导航器作为覆盖层。用户不应为了定位并打开另一个文件而离开当前编辑器标签。
- 重启恢复应保持连续：恢复配置的项目/工作区、仍存在的最后活动对话、拓展工作区宽度/折叠/全屏状态、活动/打开标签、最后打开的文件请求，以及仍打开文件标签的有界未保存文本/代码草稿。如果记住的对话已经不存在，静默清理过期指针。
- 长任务在用户关闭最后一个窗口后默认可以继续后台运行，但必须同时提供系统托盘、运行状态和明确的“彻底退出”动作，不能成为不可见后台进程。用户可以在设置中改为关闭窗口即终止/退出；切换策略时应说明对活动任务的影响。
- 关闭窗口、最小化到托盘、暂停任务、中断当前 run 和彻底退出是不同操作。彻底退出前若存在活动任务，应显示任务、当前步骤和可恢复性；若已具备检查点则允许“保存并退出”，否则必须说明会丢失哪部分现场。
- 代码/文本/脚本/配置/锁文件、Markdown，以及通过文本探测的未知扩展文件，默认进入由 Monaco 驱动的内置 VS Code 风格编辑器，并立即显示语法高亮和行号。图片和 PDF 使用媒体预览；Word/PPT/Excel 类办公文件使用文件卡片以及系统默认应用或外部编辑器入口，不进入 Monaco。外部 VS Code 仍是明确的独立动作，应用内编辑器应称为 LS 内置 VS Code 风格代码工作台。
- 内置编辑器可以使用 VS Code 的视觉语言，但必须命名并作为 LS 自有的编辑器表面处理。除非后端确实实现，不要暗示已经嵌入完整 VS Code extension host。
- 有未保存修改的文件标签必须显示紧凑脏标记；切换到其他工作区标签或重启应用后保留草稿；支持 `Ctrl+S`/`Cmd+S` 保存；关闭脏标签前询问确认。草稿恢复必须有界、只在本地生效，并且不能覆盖捕获草稿后已经在磁盘上发生变化的文件。
- 终端标签必须在 LS 内运行。Windows 上在选定工作区启动 PowerShell；命令提交遵守当前权限模式和审批策略。终端后端优先使用 node-pty/ConPTY，原生 PTY 模块加载失败时回退到普通 spawn 会话，保证原生模块异常的机器仍能启动 LS。
- PTY 模式可以提供可靠的终端控制，例如视口调整和 `Ctrl+C` 中断。“中断”和“重启会话”必须是两个独立控件：中断向当前 shell 发送 Ctrl+C/SIGINT，重启则停止 shell 并创建新会话。
- 终端原始键盘输入不得绕过权限模式。在 LS 尚未实现完整交互式终端输入的会话级授权模型前，命令执行保持在受控提交路径后，PTY 主要用于终端显示、尺寸调整、控制序列和中断。
- 终端交互必须可靠且可见：最近命令回填、上下方向键历史、`Esc` 清空输入、`Ctrl+L`/`Cmd+L` 清空输出、视口尺寸上报、明确的中断和明确的重启。在原始终端输入拥有自己的权限设计前，不要暗示支持无限制的交互式程序。
- 用户提交的终端命令必须持久化有用上下文，不能只记录“已发送”。PTY 会话要捕获从命令提交到下一条命令、中断或会话关闭之间的输出，并将摘要用于最近命令行和工作区活动。
- 外部工作区动作必须明确区分。“用系统默认应用打开”和“用 VS Code 打开”是两个独立控件，拥有各自的提示和错误信息；不要把 VS Code 行为隐藏在通用外部打开按钮后。
- 内置编辑器保存必须遵守权限模式。完全访问可以直接保存；研究/受限模式写入前必须明确确认。文件打开后若磁盘内容发生变化，保存不能静默覆盖，应显示冲突错误并要求用户刷新。
- 用户运行的终端命令属于工作区活动，不属于 Agent 工具活动。按工作区和会话持久化，重启后恢复最近命令，并以安静、可复用的活动行展示；悬浮/聚焦时显示详情，不把它们当作聊天消息。
- 工作区产物是持久活动，不只是消息内装饰。按工作区/会话/项目持久化 Agent 创建或修改的文件以及用户保存的文件，再将该索引与审查界面的实时消息产物合并，保证重启恢复连续。
- Agent 过程细节应与工作区关联。如果工具调用引用了具体文件路径，展开后的命令/详情表面应提供安静的“打开文件”动作，并打开与产物卡片相同的顶层文件标签。
- Agent 与用户活动需要双向透明。执行面板应能看到 Agent 当前步骤、工具、等待、验证和恢复状态；Agent 也只能接收 LS 明确捕获且用户已授权的追加消息、文件保存、设置变更、暂停/恢复等事件，并在事件被采纳时显示其对 TaskBook 的影响。
- 同一 TaskBook 存在并行分支时，执行面板按分支或步骤分组显示真实状态，默认折叠冗长命令输出。并行事件不能按到达顺序混成难以阅读的一条日志；最终展示应按任务依赖稳定归并，同时保留每个分支的真实开始、完成、失败和取消时间。
- 记忆更新默认安静进行，不在普通对话中刷屏。用户可以在设置中启用记忆更新提示，并在记忆树管理页查看写入来源、父节点、层级、理由、差异和撤销入口；关闭提示只影响展示，不能关闭审计记录。
- 旧执行记录必须使用与实时 Agent 活动相同的无气泡过程语言渲染。重启或加载旧 trace/toolCall 消息格式时，不能退回到单独的带框“详情卡片”。
- 产物管理器应作为拓展工作区的一等标签页。它应支持项目/会话作用域、来源和动作过滤、文本搜索及直接重新打开文件，并保持与工作区其余部分一致的安静悬浮框语言。
- 供应商/模型选择器在数据具有层级时，不要使用很长的平铺列表。只显示已配置且当前可用的供应商/模型，不要把不可用选项塞满菜单。
- 相关选择应优先使用一个带堆叠分组的紧凑主面板。模型/运行时选择应在一个面板中显示推理程度、模型和供应商，而不是打开并排的供应商和模型子菜单。
- 如果将详细选项放入子菜单能简化主界面，应这样做，但包含首次打开菜单在内，嵌套菜单最多三层。
- 与模式或权限相关的选项应显示简短的悬浮/聚焦说明，不能用会改变行高的内嵌文字。
- 浮动说明必须显示在所有面板之上。首次悬浮/聚焦要等待光标停顿 0.5 秒；如果已有说明框，光标直接移动到同一选择栏的相关选项时应立即用轻微淡入淡出更新，不能让控件感觉迟钝。
- 浮动说明应出现在光标或聚焦控件旁边，绝不能占用菜单/列表布局空间，否则会造成行跳动和不稳定的选择目标。
- 当文字是面向用户的引导时，输入栏控件应使用共享浮动说明，而不是原生 `title` tooltip。
- 输入栏附件应支持点击、拖放和粘贴，并在发送前于输入栏内显示可移除的预览卡片。
